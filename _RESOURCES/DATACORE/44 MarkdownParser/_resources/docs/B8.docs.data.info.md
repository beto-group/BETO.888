## The Datacore Environment

### The Global `dc` Object

**INFO**

The `dc` object is the global entry point provided to your components. It is not just an API; it's a complete development environment that provides the core React hooks needed to build your UI, alongside the Datacore-specific APIs for querying and file manipulation.

**Use when**

You are building any component. All React functionality (`useState`, `useEffect`, etc.) and all Datacore functionality (`api.query`) are accessed through this single, convenient object.

**Code**
```jsx
// Destructure React hooks directly from the dc object
const { useState, useEffect, useMemo, useRef } = dc;

// Access the Datacore API via dc.api
async function getFileCount() {
  const pages = await dc.api.query("@page");
  new Notice(`There are ${pages.length} pages in your vault.`);
}
```

## The Datacore Query Language (DQL)

**INFO**

DQL is a powerful, text-based language for finding specific information in your vault. Mastering its syntax is the key to unlocking Datacore's full potential. A query is composed of a **Base Type**, followed by one or more filtering **Clauses** joined by **Logical Operators**.

---

### Base Types

**Description**

The starting point of every query, defining the fundamental type of object you are looking for.

| Base Type | Description |
| :--- | :--- |
| `@page` | Finds all Markdown notes. This is the most common base type. |
| `@task` | Finds all individual tasks (`- [ ]`, `- [x]`, etc.) within all notes. |
| `@file` | Finds all files in the vault, including non-Markdown assets like images and PDFs. |
| `@section` | Finds a section of a note under a specific heading. |
| `@block` | Finds a paragraph or other distinct block-level element. |
| `@list-item`| Finds an individual item in a bulleted or numbered list. |
| `@codeblock`| Finds any fenced code block. |

---

### Clauses & Functions

**Description**

Clauses are used after the base type to filter the results down to what you need. They are typically combined with logical operators like `AND`.

| Clause / Function | Description | Example |
| :--- | :--- | :--- |
| `#tag` or `#"tag with space"` | Filters for items containing a specific tag. | `@page AND #projects/active` |
| `path("folder")` | Filters for items located inside a specific folder path. | `@task AND path("Inbox")` |
| `exists(field)` | Filters for items that have a specific frontmatter or data field. | `@page AND exists(rating)` |
| `linkedto([[note]])` | Finds items that contain a link **to** the specified note. | `@page AND linkedto([[Q4 Goals]])` |
| `linkedfrom([[note]])` | Finds items that the specified note links **from** (i.e., outgoing links). | `@task AND linkedfrom([[Meeting 2024-10-26]])` |
| `connected([[note]])` | A combination of the above; finds items linked **to OR from** the note. | `connected([[Project Mercury]])` |
| `parentof(subquery)` | Finds the direct parent object of items matching a subquery. | `parentof(@task AND #urgent)` |
| `childof(subquery)` | Finds the direct child objects of items matching a subquery. | `childof(@page AND path("Areas"))` |

---

### Logical Operators & Field Queries

**Description**

Combine clauses using logical operators. For fine-grained control, perform direct comparisons on field values.

| Type | Syntax | Description |
| :--- | :--- | :--- |
| **Operators** | `AND`, `OR` | Combine multiple clauses. `OR` has higher precedence. Use `()` for grouping. |
| **Negation**| `!` | Negates the following clause. Example: `!#archive` finds items NOT tagged archive. |
| **Field Query**| `field_name > value` | Compares a field's value. Supports `==`, `!=`, `>`, `<`, `>=`, `<=`. |
| **Field with Spaces**| `row["field name"]` | Use `row` notation for fields with spaces or special characters. |
| **Contains Method**| `field.contains("text")` | Checks if a text field or array contains a value. |

**Comprehensive Example**
```
// Find all incomplete tasks in the "Projects" folder with a high priority
// that are either due in the next 7 days OR have no due date at all.
@task
  AND path("Projects")
  AND !#done
  AND priority > 3
  AND (due <= "in 7 days" OR !exists(due))
```

## Executing Queries

### `useQuery`

**Description**

A reactive React hook that runs a DQL query and automatically re-renders your component whenever the underlying data that matches the query changes. This is the **preferred method** for any data that is actively displayed in the UI.

**Signature**
```typescript
function useQuery(query: string): any[] | undefined
```

**Code**
```jsx
const { useState } = dc;

function ActiveProjectsList() {
  const query = `@page and #project and !#archive order by $ctime desc`;
  const projects = dc.useQuery(query);

  // The hook returns undefined while the initial query is running.
  if (!projects) return <div>Loading active projects...</div>;

  return (
    <ul>
      {projects.map(project => (
        <li key={project.$path}>{project.$name}</li>
      ))}
    </ul>
  );
}
```

---

### `api.query`

**Description**

A one-shot, asynchronous function to execute a DQL query. It returns a promise with the results and does **not** update automatically. It is ideal for populating UI helpers (like a tag picker), running background tasks, or fetching data inside event handlers where reactivity is not needed.

**Signature**
```typescript
async function query(query: string): Promise<any[]>
```

**Code (Pattern from `TagHelper`)**
```javascript
// This pattern is used to populate UI helper components.
const { useState, useEffect } = dc;

function TagPicker() {
  const [allTags, setAllTags] = useState(null);

  useEffect(() => {
    async function fetchTags() {
      try {
        // 1. Fetch all pages in a single, one-shot query.
        const pages = await dc.api.query("@page");
        const tagSet = new Set();
        // 2. Process the results in JavaScript to derive the needed data.
        for (const note of pages) {
          for (const rawTag of note.$tags || []) {
            tagSet.add(rawTag.replace(/^#/, ""));
          }
        }
        // 3. Set the final, processed data into component state.
        setAllTags(Array.from(tagSet).sort());
      } catch (e) { console.error("Failed to fetch tags.", e); }
    }
    fetchTags();
  }, []); // Empty dependency array ensures this runs only once.

  if (allTags === null) return <div>Loading tags...</div>
  // ... render the tag list
}
```

## The Query Result Object

**INFO**

The items returned from a query are rich objects, not just plain JSON. They contain metadata, data from your notes, and even methods for introspection. Understanding this structure is essential for displaying data correctly.

---

### Core Metadata (`$`-prefixed)

**Description**

Special, read-only properties for essential vault metadata, available on most result objects.

| Property | Type | Description |
| :--- | :--- | :--- |
| `$path` | `string` | The full, unique path to the source file. |
| `$name` | `string` | The display name of the file (without extension). |
| `$tags` | `string[]` | An array of all tags in the file (e.g., `['#tag1', '#tag2']`). |
| `$ctime` | `LuxonDateTime` | The creation time of the file. A Luxon object. |
| `$mtime` | `LuxonDateTime` | The last modification time of the file. A Luxon object. |
| `$parent` | `object` | A reference to the parent object (e.g., the page for a task). **Can cause circular references.** |

---

### Data Properties & Methods

**Description**

Access frontmatter and other data as direct properties. Use the `fields()` method to discover all available data on an object.

| Property / Method | Description |
| :--- | :--- |
| `item.fieldName` | Access frontmatter or other data directly (e.g., `item.rating`, `item.author`). |
| `item.text` | For tasks, this contains the text content of the task itself. |
| `item.fields()`| **A key method for discovery.** Returns a structured list of all available fields and their values on the object. This is invaluable for building dynamic tools and for debugging what data is available to you. |

---

### Special Considerations

*   **Luxon Dates:** Time properties like `$ctime` are not strings or numbers; they are [Luxon DateTime](https://moment.github.io/luxon/) objects. This allows for powerful and easy formatting: `item.$ctime.toFormat("yyyy-MM-dd 'at' HH:mm")`.
*   **Circular References:** Properties like `$parent` create object cycles (`task.$parent` points to the page, and `page.$tasks` might contain the task). When serializing these objects to JSON (e.g., for debugging), you **must** use a replacer function to avoid infinite loops, as demonstrated in the explorer's `jsonReplacer`.

## Applications

*   **Dynamic Dashboards & Feeds ( [[DATACORE.flexilis.v4|DATACORE FLEXILIS]], [[CUSTOM FEED]], [[BOUNTY VIEW 🎅|BOUNTY VIEW]] )**
    *   These applications are the primary use case for live queries. They use `useQuery` to fetch and display dynamic lists of notes, tasks, or other data points from across the vault. Data Accessors (`$name`, `status`, `dueDate`) are then used to populate the columns and fields of the UI.
*   **Data Aggregators ( [[TAG VIEWER]] )**
    *   A specialized type of dashboard that first uses a broad `useQuery` (e.g., to get all notes) and then performs client-side processing on the results. The Tag Viewer aggregates all unique `$tags` from the query results to build an interactive tag hierarchy.
*   **Asset Renderers ( [[IMAGE RENDER]], [[MUSIC PLAYER]], [[LOTTIE EXPERIMENT]], [[SOUND PLAYER]])**
    *   These components are designed to render non-Markdown files. They follow a common pattern: use `fuzzyFindFile` to locate a specific asset (like `background-music.mp3` or `logo-animation.json`) by its name, then use the resulting file path to generate a renderable URL for an `<img>`, `<audio>`, or other media element.
*   **Structured Content Processors ( [[_RESOURCES/DATACORE/10 Kanban/KANBAN]], [[CARD PICKER]] )**
    *   These applications treat a single Markdown note as a collection of smaller items. They use a content utility like `parseContentToSections` to split a note's content by a `---` separator, turning each section into a card on a Kanban board or a card in a virtual deck.
*   **Hybrid Data & Asset Applications ( [[RECEIPT TRACKER]] )**
    *   This is a more advanced application that combines multiple controls from this module. It uses `useQuery` to list all receipt notes, Data Accessors to display frontmatter fields like `amount` and `date`, and `fuzzyFindFile` to locate and display the corresponding scanned image for each receipt entry.
*   **Context-Aware Tools ( [[CHATLLM]] )**
    *   Uses `api.query` in the background to find relevant notes or documents that can be used as context for a language model. This allows for Retrieval-Augmented Generation (RAG) by dynamically searching the vault for information related to the user's query.
