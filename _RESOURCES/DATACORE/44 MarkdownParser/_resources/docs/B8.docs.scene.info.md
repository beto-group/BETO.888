## External Library Management

### Loading Scripts

**INFO**

Before any advanced rendering can occur, the corresponding JavaScript library (e.g., Babylon.js, D3.js) must be loaded into the page. The recommended approach is to use a dynamic script loader that can fetch libraries from a CDN (Content Delivery Network) and intelligently cache them in the vault for offline use.

**Use when**

You are building any component that depends on a large, external JavaScript library for rendering. This pattern ensures the library is loaded efficiently and only when needed.

**Code**
```javascript
// A robust script loader that fetches from a URL and caches locally.
// For a complete implementation, see the `loadScript` helper in Module 5.
async function loadScript(src) {
  // Check if the script is already loaded to avoid re-execution
  if (window.BABYLON) { // Example check for Babylon.js
    console.log("Babylon.js is already loaded.");
    return;
  }
  
  return new Promise((resolve, reject) => {
    const script = document.createElement("script");
    script.src = src;
    script.async = true;
    script.onload = resolve;
    script.onerror = reject;
    document.body.appendChild(script);
  });
}

// Usage within a component's useEffect hook
useEffect(() => {
  async function initialize() {
    await loadScript("https://cdn.babylonjs.com/babylon.js");
    // Now that the script is loaded, window.BABYLON is available.
    // ...proceed with scene setup...
  }
  initialize();
}, []);
```

## 3D Scene Controls (Babylon.js)

**INFO**

Controls for creating and managing a 3D scene using a `<canvas>` element and the Babylon.js engine. This is the foundation for any component that requires 3D rendering.

**Use when**

You need to render 3D models, create immersive game-like worlds, or display interactive 3D visualizations.

---

### Basic Scene Setup

**Description**

Initializes the fundamental components required for any 3D rendering: the Babylon.js `Engine` attached to a `<canvas>`, a `Scene` to hold all objects, a `Camera` to view the scene, and a `HemisphericLight` for basic illumination.

**Code**
```jsx
const { useRef, useEffect } = dc;

function BasicScene() {
  const canvasRef = useRef(null);

  useEffect(() => {
    // Assumes Babylon.js is loaded via a script loader (see above)
    if (!canvasRef.current || !window.BABYLON) return;

    const engine = new BABYLON.Engine(canvasRef.current, true);
    const scene = new BABYLON.Scene(engine);
    
    const camera = new BABYLON.ArcRotateCamera("cam", -Math.PI / 2, Math.PI / 2.5, 10, BABYLON.Vector3.Zero(), scene);
    camera.attachControl(canvasRef.current, true);
    
    new BABYLON.HemisphericLight("light", new BABYLON.Vector3(0, 1, 0), scene);
    BABYLON.MeshBuilder.CreateGround("ground", { width: 6, height: 6 }, scene);
    
    engine.runRenderLoop(() => scene.render());

    // Cleanup when the component unmounts
    return () => engine.dispose();
  }, []);

  return <canvas ref={canvasRef} style={{ width: '100%', height: '100%' }} />;
}
```

### Loading a `.glb` Model

**Description**

Loads a `.glb` or `.gltf` 3D model file from the vault and adds it to the scene. This uses the Babylon.js `SceneLoader` and requires a resource path to the local vault file, obtained via `dc.app.vault.adapter.getResourcePath`.

**Code**
```javascript
async function loadGltfModel(scene, vaultPath) {
  // Assumes SceneLoader extension is also loaded
  const modelUrl = dc.app.vault.adapter.getResourcePath(vaultPath);

  try {
    const result = await BABYLON.SceneLoader.ImportMeshAsync(
      null, "", modelUrl, scene, null, ".glb"
    );
    return result.meshes[0]; // The first mesh is often the root node
  } catch (e) {
    console.error("Failed to load GLB model:", e);
    return null;
  }
}
```

## 2D Canvas & Animation

**INFO**

Controls for creating 2D graphics and procedural animations using the HTML5 `<canvas>` element. This provides a performant way to render visuals that are too complex or dynamic for standard DOM elements.

**Use when**

You need to create dynamic, animated backgrounds, generative art, custom UI elements, or complex vector animations that CSS cannot easily handle.

---

### 2D Render Loop

**Description**

Sets up a basic `requestAnimationFrame` loop. This is the fundamental pattern for any continuous 2D animation, ensuring smooth rendering that is synchronized with the browser's display refresh rate.

**Code (Pattern from `FuzzyText` and `MatrixGlitchWall`)**
```jsx
const { useRef, useEffect } = dc;

function My2dAnimation() {
  const canvasRef = useRef(null);
  const animationFrameId = useRef(null);

  useEffect(() => {
    const canvas = canvasRef.current;
    const ctx = canvas.getContext('2d');
    let frame = 0;

    const render = () => {
      frame++;
      ctx.clearRect(0, 0, canvas.width, canvas.height);
      ctx.fillStyle = 'white';
      ctx.fillText(`Frame: ${frame}`, 10, 20);
      animationFrameId.current = requestAnimationFrame(render);
    };

    render();
    return () => cancelAnimationFrame(animationFrameId.current);
  }, []);

  return <canvas ref={canvasRef} width="300" height="150" />;
}
```

## Applications

*   **Immersive 3D Worlds ( [[WORLD 888]], [[GAME ENGINE BUILD]],  [[BABYLON LOCAL]] )**
    *   These components are built entirely on the **3D Scene Controls**. They begin by **Loading Scripts** for Babylon.js and its loaders. Then, they use `Basic Scene Setup` to create the world and `Loading a .glb Model` to populate it with environments. Custom render loops add interactivity and physics.
*   **Dynamic 3D Objects ( [[ANIMATED CARD]] )**
    *   A focused use of 3D controls. After **Loading Scripts** for Babylon.js, it combines `Basic Scene Setup` with the **Video Texture** pattern to create a visually rich, self-contained 3D object with animated surfaces.
*   **Generative Art & Effects ( [[MATRIX GLITCH WALL]], [[FUZZY TEXT]] )**
    *   These are pure implementations of the **2D Render Loop**. They use a `<canvas>` element and `requestAnimationFrame` to continuously draw and update thousands of individual elements, creating procedural visual effects.
*   **Vector Animation ( [[LOTTIE EXPERIMENT]], [[AQUARIUM]], [[IMAGE RENDER]] )**
    *   These components use the **Lottie Animation Player** pattern, which includes **Loading Scripts** for the `<lottie-player>` web component, to render complex, pre-designed vector animations as backgrounds or interactive elements.
*   **Data Dashboards ( [[ACTIVITYWATCH DASHBOARD]], [[RECEIPT TRACKER]], [[D3.JS TEST]] )**
    *   These components use the **D3 Setup** pattern, which involves **Loading Scripts** for the D3.js library, and then implement various **Chart Implementation** patterns to render data into interactive bar charts, pie charts, and heatmaps.
*   **Interactive Diagrams ( [[FITNESS EXPLORER]], [[BOUNTY VIEW 🎅]] )**
    *   These use **SVG Interaction** by embedding complex SVG code directly into the component and attaching `onClick` and `onMouseEnter` handlers to specific SVG `<g>` (group) elements to make parts of the diagram clickable and interactive.
