# MODULE 3 — UI & INTERACTION

This module provides the core controls and patterns for building rich, interactive user interfaces. These patterns handle complex tasks like rendering large datasets, managing drag-and-drop interactions, and creating sophisticated navigation structures, ensuring a consistent and high-performance user experience across all Datacore components.

---

## Catalog

*   **Data Display & Layout**
    *   **Custom Table:** Building interactive tables from scratch with full control over rendering.
    *   **Pagination & Virtualization:** High-performance strategies for displaying large datasets.
    *   **Grouping:** Organizing table rows into collapsible sections based on a data field.
*   **Drag & Drop**
    *   **Draggable Item:** Making a UI element movable to trigger actions or reorder data.
    *   **Drop Target:** Defining an area that accepts draggable items.
    *   **Column Reordering:** Applying drag-and-drop to table headers to reorder columns.
    *   **Drag-out to Obsidian:** Creating draggable links for the main Obsidian editor.
*   **Navigation & State**
    *   **Hierarchical State:** Managing drill-down navigation state using a path array.
    *   **Breadcrumbs:** Displaying the current path and allowing jumps to parent levels.
*   **Windowing & Screen Management**
    *   **Screen Mode Helper:** A utility for creating PiP, fullscreen, or floating window modes.
*   **Interactive Graphics**
    *   **SVG Interaction:** Attaching event handlers to SVG groups for clickable diagrams.
    *   **3D & Canvas Rendering:** Using a `<canvas>` ref to integrate with 3D libraries like Babylon.js.

## Data Display & Layout

**INFO**

Controls and patterns for rendering structured data (typically from `dc.useQuery`) into dynamic, feature-rich tables and lists. This is the foundation for any component that presents data to the user.

**Use when**

You need to display query results in a tabular format, handle thousands of rows smoothly, or implement advanced features like column reordering, pagination, and data grouping.

---

### Custom Table

**Description**

Building a table from scratch using standard HTML elements (like `<div>`s styled with flexbox) and Datacore state management. This offers maximum flexibility for custom features like dynamic columns, complex cell renderers, and integrated actions.

**Code (Pattern from `DATACORE.flexilis`)**
```jsx
function CustomDataTable({ rows, columns }) {
  const STYLES = {
    table: { display: 'flex', flexDirection: 'column' },
    headerRow: { display: 'flex', fontWeight: 'bold', borderBottom: '1px solid #555' },
    row: { display: 'flex', borderBottom: '1px solid #333' },
    cell: { flex: '1 0 150px', padding: '8px', overflow: 'hidden', whiteSpace: 'nowrap' },
  };

  return (
    <div style={STYLES.table}>
      <div style={STYLES.headerRow}>
        {columns.map(col => <div style={STYLES.cell} key={col.key}>{col.title}</div>)}
      </div>
      {rows.map(row => (
        <div style={STYLES.row} key={row.$path}>
          {columns.map(col => <div style={STYLES.cell} key={col.key} title={row[col.key]}>{row[col.key]}</div>)}
        </div>
      ))}
    </div>
  );
}
```

### Pagination & Virtualization

**INFO**

High-performance strategies for rendering large datasets (100 to 100,000+ items) without freezing the UI. **Pagination** breaks data into discrete pages, while **Virtualization** creates the illusion of a seamless, infinitely long list by only rendering the items currently visible in the viewport.

**When to Use Which**

*   **Standard Pagination:** Use when you want explicit page controls (`Prev`, `Next`, page numbers). This is user-friendly for reports and when the total number of items is important to display.
*   **High-Performance Virtualization:** Use when you want a seamless, "infinite scroll" experience for potentially massive lists where explicit pages are less important than smooth browsing. This is ideal for power-user tools that handle thousands of rows.

---

#### Standard Pagination

**Description**

A client-side pattern for breaking a large dataset into manageable pages. A `useState` hook tracks the current page number, and `useMemo` is used to efficiently compute the "slice" of data visible on that page.

**Code**
```jsx
const { useState, useMemo } = dc;
const ITEMS_PER_PAGE = 50;

function PaginatedList({ allData }) {
  const [currentPage, setCurrentPage] = useState(1);
  const totalPages = Math.ceil(allData.length / ITEMS_PER_PAGE);

  const paginatedData = useMemo(() => {
    const start = (currentPage - 1) * ITEMS_PER_PAGE;
    return allData.slice(start, start + ITEMS_PER_PAGE);
  }, [allData, currentPage]);
  
  return (
    <div>
      {/* Render your paginatedData here */}
      <div className="pagination-controls">
        <button onClick={() => setCurrentPage(p => Math.max(1, p - 1))} disabled={currentPage === 1}>Prev</button>
        <span> Page {currentPage} of {totalPages} </span>
        <button onClick={() => setCurrentPage(p => Math.min(totalPages, p + 1))} disabled={currentPage === totalPages}>Next</button>
      </div>
    </div>
  );
}
```

#### High-Performance Virtualization

**Description**

A more advanced technique that achieves extreme performance by only rendering the DOM nodes for rows that are currently visible within a scrollable container. It uses spacer elements to create a scrollbar that accurately represents the full height of all potential items, giving the user a seamless experience even with tens of thousands of rows. This pattern is critical for components like `DATACORE.flexilis` that must handle ungrouped, unfiltered query results.

**Core Concepts**

1.  **Scroll Container:** An outer `div` with a fixed height and `overflow-y: auto` that serves as the viewport.
2.  **Row Height Measurement:** Since rows can have variable heights (e.g., due to wrapped text), each row's actual height must be measured after it renders. This is done using a `useRef` on the row's DOM element and a callback to update a state object (`rowHeights`) that maps each row's index to its measured height.
3.  **State Management:** The component must track the container's `scrollTop`, the container's height, and the measured height of every row.
4.  **Calculating Visible Rows:** Using the `scrollTop` and row heights, the component calculates the `startIndex` and `endIndex` of the data array that corresponds to the visible rows. An "overscan" count is added to render a few extra rows above and below the viewport, preventing flickering during fast scrolling.
5.  **Spacers:** Two "spacer" `<div>` or `<tr>` elements are rendered. A top spacer is given a height equal to the total height of all rows *before* the visible ones. A bottom spacer is given a height equal to all rows *after* the visible ones. This creates the correct total scroll height.

**Code (Pattern from `VirtualizedTable` in `DATACORE.flexilis`)**
```jsx
function VirtualizedList({ data }) {
  const defaultRowHeight = 50; // An estimate for unmeasured rows.
  const [rowHeights, setRowHeights] = useState({});
  const containerRef = useRef(null);
  const [scrollTop, setScrollTop] = useState(0);
  const [containerHeight, setContainerHeight] = useState(0);

  // Measure container on mount and resize.
  useEffect(() => {
    if (containerRef.current) {
      setContainerHeight(containerRef.current.clientHeight);
      const resizeObserver = new ResizeObserver(entries => {
        setContainerHeight(entries[0].contentRect.height);
      });
      resizeObserver.observe(containerRef.current);
      return () => resizeObserver.disconnect();
    }
  }, []);

  // Throttled scroll handler.
  const handleScroll = e => {
    window.requestAnimationFrame(() => setScrollTop(e.target.scrollTop));
  };
  
  // Calculate cumulative heights for fast lookups.
  const cumulativeHeights = useMemo(() => {
    let total = 0;
    return data.map((_, i) => (total += rowHeights[i] || defaultRowHeight));
  }, [data, rowHeights]);

  // Find the start and end index of visible rows.
  const startIndex = /* ... binary search on cumulativeHeights with scrollTop ... */;
  const endIndex = /* ... binary search for scrollTop + containerHeight ... */;
  
  // Render a few extra rows for smoothness (overscan).
  const overscan = 5;
  const visibleStartIndex = Math.max(0, startIndex - overscan);
  const visibleEndIndex = Math.min(data.length, endIndex + overscan);
  const visibleRows = data.slice(visibleStartIndex, visibleEndIndex);

  // Calculate spacer heights.
  const totalHeight = cumulativeHeights[data.length - 1] || 0;
  const topSpacerHeight = visibleStartIndex > 0 ? cumulativeHeights[visibleStartIndex - 1] : 0;
  const bottomSpacerHeight = totalHeight - (visibleEndIndex > 0 ? cumulativeHeights[visibleEndIndex - 1] : 0);

  const updateRowHeight = (index, height) => {
    if (rowHeights[index] !== height) {
      setRowHeights(prev => ({ ...prev, [index]: height }));
    }
  };

  return (
    <div ref={containerRef} onScroll={handleScroll} style={{ height: '100%', overflowY: 'auto' }}>
      <div style={{ height: totalHeight, position: 'relative' }}>
        {/* Top spacer creates the space for scrolled-past items */}
        <div style={{ height: topSpacerHeight }} />
        
        {/* Render only the visible rows */}
        {visibleRows.map((row, index) => {
          const globalIndex = visibleStartIndex + index;
          return <RowComponent key={row.id} row={row} updateHeight={updateRowHeight} index={globalIndex} />;
        })}

        {/* Bottom spacer creates the space for upcoming items */}
        <div style={{ height: bottomSpacerHeight }} />
      </div>
    </div>
  );
}
```

### Grouping

**Description**

A pattern for organizing rows in a custom table into collapsible sections based on the value of a specific field. This transforms a flat list into a structured, hierarchical view.

**Code (Pattern from `DATACORE.flexilis`)**
```jsx
function GroupedTable({ allData, groupByField }) {
  const groupedData = useMemo(() => {
    if (!groupByField) return null;
    const groups = {};
    allData.forEach(entry => {
      const key = entry[groupByField] || "Uncategorized";
      if (!groups[key]) groups[key] = [];
      groups[key].push(entry);
    });
    return Object.keys(groups).sort().map(key => ({ key, items: groups[key] }));
  }, [allData, groupByField]);

  if (!groupedData) return <CustomDataTable rows={allData} />;
  
  return (
    <div>
      {groupedData.map(group => (
        <div key={group.key}>
          <div className="group-header">{group.key} ({group.items.length})</div>
          {group.items.map(item => <div key={item.$path}>{item.$name}</div>)}
        </div>
      ))}
    </div>
  );
}
```

## Drag & Drop

**INFO**

Controls for making UI elements physically movable to trigger actions or reorder data. These patterns rely on the native HTML5 Drag and Drop API.

**Use when**

You need to implement reordering, Kanban-style boards, or allow users to drag data out of your component into an Obsidian note.

---

### Draggable Item

**Description**

Makes a component draggable using the `draggable` attribute. The `onDragStart` handler attaches the necessary data (typically a unique ID) for the drop target to consume.

**Code**
```jsx
function DraggableCard({ itemData }) {
  const handleDragStart = (e) => {
    // The 'itemId' is what identifies the data being moved.
    e.dataTransfer.setData("text/plain", itemData.id);
    e.dataTransfer.effectAllowed = "move";
  };

  return (
    <div draggable onDragStart={handleDragStart}>
      {itemData.content}
    </div>
  );
}
```

---

### Drop Target

**Description**

Defines an area that can accept a drop. The `onDrop` handler reads the data from the event and performs an action. **Crucially**, `onDragOver` must call `e.preventDefault()` to signal that a drop is allowed.

**Code**
```jsx
function KanbanColumn({ columnId, onDropItem }) {
  const handleDrop = (e) => {
    e.preventDefault();
    const itemId = e.dataTransfer.getData("text/plain");
    // Notify a parent component to update the state.
    onDropItem(itemId, columnId);
  };

  const handleDragOver = (e) => {
    e.preventDefault(); // This is required to allow dropping.
    e.dataTransfer.dropEffect = "move";
  };

  return (
    <div onDrop={handleDrop} onDragOver={handleDragOver}>
      {/* Render cards here */}
    </div>
  );
}
```

### Column Reordering

**Description**

A specific application of the Draggable Item and Drop Target patterns to allow users to reorder the columns in a custom table. Each column header is a draggable item, and it can be dropped onto another header to change its position in the columns array.

**Code (Pattern from `DraggableEditBlock` in `DATACORE.flexilis`)**
```jsx
function DraggableColumnHeader({ column, index, onReorder }) {
  const handleDragStart = (e) => {
    e.dataTransfer.setData("draggedColumnIndex", index);
  };

  const handleDrop = (e) => {
    const draggedIndex = parseInt(e.dataTransfer.getData("draggedColumnIndex"), 10);
    const dropIndex = index;
    // Notify parent to reorder the columns array state.
    onReorder(draggedIndex, dropIndex); 
  };
  
  const handleDragOver = (e) => e.preventDefault();

  return (
    <div draggable onDragStart={handleDragStart} onDrop={handleDrop} onDragOver={handleDragOver}>
      {column.title}
    </div>
  );
}
```

### Drag-out to Obsidian

**Description**

A specialized drag pattern where the data set in `onDragStart` is a formatted wikilink or tag. This allows the user to drag an item from your component directly into an Obsidian note editor to create a link.

**Code (Pattern from `DraggableLink` in `DATACORE.flexilis`)**
```jsx
function DraggableWikiLink({ note }) {
  const handleDragStart = (e) => {
    // The data is a plain text string in a format Obsidian understands.
    const linkText = `[[${note.$path}]]`;
    e.dataTransfer.setData("text/plain", linkText);
    e.dataTransfer.effectAllowed = "copy";
  };

  return (
    <a href="#" draggable onDragStart={handleDragStart}>
      {note.$name}
    </a>
  );
}
```

## Navigation & State

**INFO**

Controls for building UIs that navigate through nested or hierarchical data structures.

**Use when**

You are building a file explorer, a nested tag browser, or any UI where users can "drill down" into deeper levels of data and need a clear way to navigate back.

---

### Hierarchical State

**Description**

Managing the navigation path using a state array. Each element in the array represents a level in the hierarchy (e.g., a sub-tag or folder name). Modifying this array drives the UI.

**Code (Pattern from `TagViewer`)**
```jsx
const { useState } = dc;

function TagBrowser() {
  // e.g., ['projects', 'active'] represents the tag #projects/active
  const [currentPath, setCurrentPath] = useState([]);

  // To navigate one level deeper:
  const drillDown = (nextLevel) => {
    setCurrentPath(prev => [...prev, nextLevel]);
  };

  // To go back up one level:
  const goBack = () => {
    setCurrentPath(prev => prev.slice(0, -1));
  };
  
  // The UI then renders content based on the data at the currentPath...
  return <div>{/* UI elements that call drillDown and goBack */}</div>;
}
```

---

### Breadcrumbs

**Description**

A UI element that visually represents the `currentPath` state array, allowing the user to see their current location in the hierarchy and jump directly to any parent level.

**Code (Pattern from `TagViewer`)**
```jsx
function Breadcrumbs({ path, onNavigateToLevel }) {
  return (
    <div className="breadcrumbs">
      <button onClick={() => onNavigateToLevel(-1)}>Home</button>
      {path.map((segment, index) => (
        <span key={index}>
          {' / '}
          <button onClick={() => onNavigateToLevel(index)}>
            {segment}
          </button>
        </span>
      ))}
    </div>
  );
}
```

## Applications

- **Advanced Data Tables ( [[DATACORE.flexilis.v4|DATACORE FLEXILIS]], [[RECEIPT TRACKER]], [[ACTIVITYWATCH DASHBOARD]] )**
    - These components are powerful examples built on the **Custom Table** pattern. DATACORE.flexilis is the most comprehensive implementation, demonstrating a sophisticated combination of UI controls:
        - **High-Performance Rendering**: It intelligently switches between standard **Pagination** (for manageable, paged views) and a variable-height **Virtualization** engine to seamlessly scroll through thousands of ungrouped rows without performance loss.
        - **Interactive Headers**: Uses **Draggable Items** and **Drop Targets** to enable dynamic **Column Reordering**.
        - **Structured Viewing**: Implements state-driven **Grouping** to organize flat data into collapsible, hierarchical sections.
        - **Obsidian Integration**: Leverages **Drag-out to Obsidian** to allow users to create wikilinks from table rows with a simple drag.
    - Simpler implementations like ReceiptTracker and ActivityWatchDashboard use the same foundational **Custom Table** and **Pagination** controls to present data in a clean, organized way.
        
- **Kanban Boards ( [[KANBAN v2]] )**
    - A classic implementation of drag-and-drop. It uses **Draggable Items** for the cards and **Drop Targets** for the columns to manage state changes by moving items between files.

- **Hierarchical Browsers ( [[TAG VIEWER]] )**
    - Demonstrates deep navigation. It relies on **Hierarchical State** to manage the current tag path and renders **Breadcrumbs** to display it. It also uses **Drag-out to Obsidian** for both tags and notes.
        
- **Interactive Graphics ( [[FITNESS EXPLORER]] , [[BOUNTY VIEW 🎅]] )**
    - These components render complex SVGs and attach onClick and onMouseEnter handlers to specific `<g>` (group) elements. This allows a static image to become a fully interactive navigation map or diagram.
        
- **3D & Canvas Rendering ([[GAME ENGINE BUILD]], [[WORLD 888]], [[ANIMATED CARD]] )**
    - This pattern uses a `<canvas>` element managed by a useRef hook as a target for a 3D rendering library like Babylon.js. All interaction logic (keyboard, mouse) is then captured by the canvas and handled by the game engine's render loop.
        
- **Windowing & Pop-outs ( [[VIEWS INCEPTIONS v1]], [[LICENSE AGREEMENT]], [[MOBILE MUSIC PLAYER]] )**
    - These components use a **Screen Mode Helper** utility to change how their container is rendered. They can break out of the standard note view to become a floating Picture-in-Picture window or fill the entire Obsidian tab for a more immersive experience.
