# MODULE 4 — WINDOWING & DISPLAY

This module provides the foundational patterns for controlling how and where components are rendered on the screen. It moves beyond simple inline views, enabling developers to create immersive, multi-window, and context-aware application experiences.

---

## Catalog

*   **Display Mode Management** (For a single component instance)
    *   **Controller:** A helper component for toggling a component's display state. (`<ScreenModeHelper>`)
    *   **API:** A function to programmatically trigger mode changes. (`helperRef.toggleMode()`)
    *   **Modes:** Different presentation styles (`default`, `window`, `fullTab`, `pip`, `character`/`float`).
*   **Dynamic Window Spawning** (For creating new component instances)
    *   **API:** A function to dynamically create and render a new floating window. (`spawnCustomPiP()`)
    *   **Container:** The internal component that provides the window frame and behavior. (`<FreshPip>`)
*   **Window State Management**
    *   **Stacking:** Automatic z-index management to bring the active window to the front.
    *   **Persistence:** Notes on saving window positions across sessions.

## Display Mode Management

**INFO**

Controls that allow a single component instance to dynamically change its own container and presentation style. The component is detached from its original location in the document and re-parented (e.g., to `document.body` or a workspace pane) to achieve fullscreen, windowed, or floating effects.

**Use when**

You need to offer an "immersive" or "focus" mode for a component, such as a 3D world, a distraction-free editor, or an expanded dashboard.

---

### `<ScreenModeHelper>`

**Description**

A controller component that provides the logic and UI buttons for switching modes. It handles the complex DOM manipulation of detaching and re-parenting the component's container, storing a reference to the original parent to ensure it can be restored correctly when returning to `default` mode.

**Signature**
```jsx
<ScreenModeHelper
  helperRef={refObject}
  containerRef={refObject}
  canvasRef={refObject} // Optional, for native PiP
  defaultStyle={string} // CSS string for default mode
  originalParentRefForWindow={refObject} // Ref to store original parent
  originalParentRefForPiP={refObject} // Ref for character/float mode parent
  allowedScreenModes={string[]} // Array of enabled modes
  engine={babylonEngine} // Optional, for resizing 3D canvas
/>
```

---

### Display Modes Explained

The `<ScreenModeHelper>` can manage several distinct display modes, each with a specific purpose and behavior.

| Mode Name | Behavior & Mechanism | Use Case |
| :--- | :--- | :--- |
| `default` | The component renders normally within the document flow of the note. This is the baseline state. | Standard inline views. |
| `browser` | Uses the browser's native Fullscreen API (`requestFullscreen()`) to make the component's container fill the entire screen, hiding all browser and Obsidian UI. | The most immersive experience for games, videos, or presentations. |
| `window` | Detaches the component and re-parents it to `document.body` with fixed positioning to fill the entire application window (viewport). Hides the Obsidian UI but keeps browser tabs visible. | A "focus mode" that provides more screen real estate without completely taking over the screen. |
| `fullTab` | Detaches the component and re-parents it to the active Obsidian workspace pane (`.workspace-leaf-content`), making it fill the current tab. | Expanding a component to fill its available pane, like maximizing a view in a multi-pane layout. |
| `pip` | **View-Only Picture-in-Picture.** Uses the browser's native Picture-in-Picture API, which requires a `<canvas>` element. It creates a floating window that stays on top of *all other applications* on your OS, but it is **not interactive**. The original component is hidden while PiP is active. | Monitoring a live-updating graphic or video feed while working in another application. |
| `character` / `float` | **Interactive Floating Window.** Detaches the component and re-parents it to `document.body` with custom fixed positioning and styling, creating a draggable and resizable "in-app" window. This window remains **within Obsidian** but floats above the note content. | Creating tool palettes, secondary displays, or mini-apps like a music player that can be moved around while you work in your notes. |

---

### `helperRef.toggleMode()`

**Description**

An imperative function exposed by the `<ScreenModeHelper>` via the `helperRef`. It allows you to programmatically trigger a mode change from within your component's logic, such as in response to a custom button click or another event.

**Signature**
```typescript
function toggleMode(mode: 'default' | 'browser' | 'window' | 'pip' | 'character'): void
```

**Code**
```jsx
// --- Inside a component using the ScreenModeHelper ---
const helperRef = useRef(null);

// A custom button inside your UI that triggers a mode change
const handleEnterFocusMode = () => {
  if (helperRef.current) {
    helperRef.current.toggleMode('window');
  }
};

// Or, trigger based on an event in a 3D scene
scene.onPointerObservable.add((pointerInfo) => {
  if (/* user clicks a specific mesh */) {
    helperRef.current?.toggleMode('pip');
  }
});
```

## Dynamic Window Spawning

**INFO**

Controls for creating new, fully independent floating windows at runtime. Unlike the multi-mode system which alters an existing component, this pattern spawns a completely new instance of *any* specified component inside its own draggable, resizable window.

**Use when**

You need to create "in-app" pop-up windows, tool palettes, secondary displays, or enable a true multi-window application experience, as seen in `ViewsInceptions` and `World888`.

---

### `spawnCustomPiP()`

**Description**

The core function for creating new windows, exposed on the `helperRef` of a `<ScreenModeHelper>`. It uses `dc.require` internally to dynamically load the target component's code from its source file and then renders it into a `<FreshPip>` container, which is appended to the document body.

**Signature**
```typescript
async function spawnCustomPiP(
  filePath: string,
  header: string,
  functionName: string,
  options?: { width?: string; height?: string; top?: string; left?: string; }
): Promise<void>
```

**Code**
```jsx
// --- In any component that has access to a ScreenModeHelper's ref ---

async function openMusicPlayerInWindow() {
  // Assume 'screenHelperRef' is a valid ref to a ScreenModeHelper instance.
  if (screenHelperRef.current) {
    screenHelperRef.current.spawnCustomPiP(
      // 1. Path to the component's .md file
      "_RESOURCES/DATACORE/36 MusicPlayer/D.q.musicplayer.component.md",
      // 2. Header name within the file
      "ViewComponent",
      // 3. Function/Component name to render
      "MusicPlayer",
      // 4. Optional styling for the spawned window
      {
        width: "380px",
        height: "600px",
        top: "100px",
        left: "100px",
      }
    );
  }
}
```

---

### `<FreshPip>`

**Description**

The internal component that provides the window "chrome" (frame, close button) and hosts the dynamically loaded component. **You do not use this component directly.** It is rendered automatically by `spawnCustomPiP`. Its implementation includes all the necessary logic for dragging, resizing, and z-index management.

---

## Window State Management

**INFO**

Patterns for managing the state of multiple floating windows, such as their stacking order.

**Use when**

You have multiple floating windows spawned via `spawnCustomPiP` and need to ensure that the most recently interacted-with window appears on top of the others.

---

### Z-Index Management

**Description**

An automatic global system that tracks the highest `z-index` among all active `<FreshPip>` windows. A `pointerdown` event on any part of a pip's container will trigger a function that brings that window to the front by assigning it a new, higher `z-index`. This behavior is built-in and requires no extra configuration.

**Code (Conceptual Example)**
```javascript
// This logic is built into the FreshPip component.
// No user code is needed to enable it.

let highestZIndex = 10000; // Global tracker

function bringToFront(container) {
  // 1. Find the current highest z-index among all '.fresh-pip' elements.
  document.querySelectorAll('.fresh-pip').forEach(el => {
    const z = parseInt(window.getComputedStyle(el).zIndex, 10) || 0;
    if (z > highestZIndex) highestZIndex = z;
  });

  // 2. Assign a new, higher z-index to the target container.
  container.style.zIndex = highestZIndex + 1;
}

// A listener on the FreshPip container automatically triggers this function.
// container.addEventListener("pointerdown", () => bringToFront(container));
```

## Applications

*   **Immersive Views & Focus Modes ( [[VIEWS CONTROL]], [[WORLD 888]], [[ACTIVITYWATCH DASHBOARD]] )**
    *   These components use the **`<ScreenModeHelper>`** to manage their own display. A 3D world can go fullscreen, or a dashboard can expand to fill the entire tab, providing a more focused user experience. The helper manages the complexity of moving the component's container in the DOM and restoring it.
*   **Modal Dialogs ( [[LICENSE AGREEMENT]] )**
    *   A specialized use of the **`<ScreenModeHelper>`**. It is configured to start in `window` mode with its toggle buttons hidden, effectively creating a mandatory modal dialog that overlays the entire application until the user completes the required actions.
*   **Dynamic "Pop-out" Windows ([[VIEWS INCEPTIONS]], [[WORLD 888]] )**
    *   These are the primary examples of the **`spawnCustomPiP()`** pattern. They provide UI elements (like a form or clickable 3D objects) that, when interacted with, dynamically load and render entirely new component instances in their own draggable, resizable windows. This creates a multi-tasking, desktop-like environment.
*   **Launchers ( [[MOBILE MUSIC PLAYER]] )**
    *   A simple button component that exists only to call **`spawnCustomPiP()`**, launching a more complex component (the full music player) in a floating window. This separates the trigger from the main application, keeping the initial UI clean.
