## File Controls

**INFO**



Core file/folder operations for creating structure and moving data around the vault. These functions are hardened with error handling and leverage Obsidian's APIs for safety.

**Use when**

You need to create files on demand, rename/move notes, or ensure folders exist without worrying about edge cases like a file already existing where a folder should be.

---

### `fileExists`

Checks if a file or folder exists at the given path. This is a safe, synchronous check.

**Signature**
```typescript
function fileExists(path: string): boolean
```

**Code**
```javascript
function fileExists(path) {
  const { normalizePath } = dc.obsidian;
  return !!dc.app.vault.getAbstractFileByPath(normalizePath(path));
}
```

**Usage Example**
```javascript
if (dc.fileExists("daily/2025-09-02.md")) {
  console.log("Today's note already exists!");
} else {
  await dc.writeFile("daily/2025-09-02.md", "# Tuesday");
}
```

---

### `ensureFolder`

Ensures a folder exists at the given path. If it, or any of its parent folders, do not exist, they will be created. It will throw an error if a *file* already exists at that path.

**Signature**
```typescript
async function ensureFolder(folderPath: string): Promise<void>
```

**Code**
```javascript
async function ensureFolder(folderPath) {
  const { TFolder, normalizePath } = dc.obsidian;
  const p = normalizePath(folderPath);
  const af = dc.app.vault.getAbstractFileByPath(p);

  if (!af) {
    await dc.app.vault.createFolder(p);
  } else if (!(af instanceof TFolder)) {
    throw new Error(`Path exists but is not a folder: ${p}`);
  }
}
```

**Usage Example**
```javascript
// This will create both 'Projects' and 'Projects/New Initiative'
await dc.ensureFolder("Projects/New Initiative");
```

---

### `writeFile`

Writes content to a file. It intelligently handles both creating new files and modifying existing ones. If parent folders don't exist, it creates them first.

**Signature**
```typescript
async function writeFile(path: string, content: string): Promise<void>
```

**Code**
```javascript
async function writeFile(path, content) {
  const { TFile, normalizePath } = dc.obsidian;
  const p = normalizePath(path);
  const af = dc.app.vault.getAbstractFileByPath(p);

  if (af && af instanceof TFile) {
    await dc.app.vault.modify(af, content);
  } else {
    const parent = p.split('/').slice(0, -1).join('/');
    if (parent) await ensureFolder(parent); // Assumes ensureFolder is available
    await dc.app.vault.create(p, content);
  }
}
```

**Usage Example**
```javascript
const frontmatter = "---\ntags: [project, inbox]\n---\n";
const noteBody = "# My New Project Idea";
await dc.writeFile("Projects/New Initiative/Idea.md", `${frontmatter}\n${noteBody}`);
```

### `renameFile`

Renames or moves a file to a new path. It will automatically create parent folders for the destination if they don't exist.

**Signature**
```typescript
async function renameFile(fromPath: string, toPath: string): Promise<void>
```

**Code**
```javascript
async function renameFile(fromPath, toPath) {
  const { TFile, normalizePath } = dc.obsidian;
  const af = dc.app.vault.getAbstractFileByPath(normalizePath(fromPath));
  if (!af || !(af instanceof TFile)) {
    throw new Error(`File not found or not a file: ${fromPath}`);
  }
  const parent = toPath.split('/').slice(0, -1).join('/');
  if (parent) await ensureFolder(parent); // Assumes ensureFolder is available
  await dc.app.vault.rename(af, normalizePath(toPath));
}
```

**Usage Example**
```javascript

```

### `listFiles` and `listFilesIn`

Returns a list of all `TFile` objects in the vault, or optionally, only those within a specific folder.

**Signature**
```typescript
function listFiles(): TFile[]
function listFilesIn(folderPrefix: string): TFile[]
```

**Code**
```javascript
// List all files in the entire vault.
function listFiles() {
  return dc.app.vault.getFiles();
}

// List all files inside a given folder path.
function listFilesIn(folderPrefix) {
  const { normalizePath } = dc.obsidian;
  const p = normalizePath(folderPrefix).replace(/\/+$/, '') + '/';
  return dc.app.vault.getFiles().filter(f => f.path.startsWith(p));
}
```

**Usage Example**
```javascript
// Get all image attachments in the vault
const allImages = dc.listFiles().filter(f => f.extension.match(/^(png|jpg|jpeg|gif)$/i));

// Get all notes in the 'Daily Notes' folder for the current year
const dailyNotes = dc.listFilesIn("Daily Notes/2024");
```

**INFO**

Direct text manipulation for Markdown content. These are the core functions for reading from and writing to the body of your notes.

**Use when**

**Description**

### `appendFile` / `prependFile`

**Description**

Adds text to the end (`appendFile`) or beginning (`prependFile`) of a file, creating the file if it doesn't exist. Automatically handles newlines.

**Signature**
```typescript
async function appendFile(path: string, text: string): Promise<void>
async function prependFile(path: string, text: string): Promise<void>
```

**Code**
```javascript
async function appendFile(path, text) {
  // Assumes readFile and writeFile helpers are available
  const cur = await dc.readFile(path).catch(() => '');
  await dc.writeFile(path, cur ? `${cur}\n${text}` : text);
}

async function prependFile(path, text) {
  const cur = await dc.readFile(path).catch(() => '');
  await dc.writeFile(path, text + (cur ? `\n${cur}` : ''));
}
```

**Usage Example**
```javascript
// Add a new entry to a running log file

await dc.appendFile("logs/system.log.md", newLogEntry);
```

### `applyEdits`

**Description**

Applies an array of precise text edits to a file. This is more efficient than a full read/write cycle for complex, non-sequential changes. An `edit` is an object: `{ from: number, to: number, text: string }`.

**Signature**
```typescript
type TextEdit = { from: number; to: number; text: string };
async function applyEdits(path: string, edits: TextEdit[]): Promise<void>
```

**Code**
```javascript
async function applyEdits(path, edits) {
  let content = await dc.readFile(path);
  // Apply edits from the end to the start to preserve character indices
  const sorted = [...edits].sort((a, b) => b.from - a.from);
  
  for (const e of sorted) {
    content = content.slice(0, e.from) + e.text + content.slice(e.to);
  }
  await dc.writeFile(path, content);
}
```

**Usage Example**
```javascript
// Example: Correcting two typos at once
const edits = [
  { from: 12, to: 15, text: "quick" }, // Fix 'qik' at index 12
  { from: 21, to: 24, text: "brown" }  // Fix 'brwn' at index 21
];
await dc.applyEdits("my-note.md", edits);
```

### `replaceSegment`

**Description**

Replaces the first occurrence of a string or regex pattern in a file.

**Signature**

```

**Code**

async function replaceSegment(path, needle, replacement) {
  const text = await dc.readFile(path);
  const next = text.replace(needle, replacement);
  if (text !== next) { // Only write if a change was made
    await dc.writeFile(path, next);
  }
}
```

### `regexReplace`

**Description**

Performs multiple, complex replacements in a file using a regex with a global flag and an evaluator function that generates the replacement for each match.

**Signature**
```typescript
async function regexReplace(path: string, regex: RegExp, replacerFn: (match: RegExpExecArray) => string): Promise<void>
```

**Code**
```javascript
async function regexReplace(path, regex, replacerFn) {
  // Ensure the regex has the global flag for multiple replacements
  if (!regex.global) {
    throw new Error("Regex must have the global 'g' flag for regexReplace.");
  }
  const text = await dc.readFile(path);
  const next = text.replace(regex, (...args) => replacerFn(args));
  await dc.writeFile(path, next);
}
```

**Usage Example**
```javascript
// Find all instances of [[wikilinks]] and wrap them in bold
const linkRegex = /\[\[(.*?)\]\]/g;
await dc.regexReplace("my-note.md", linkRegex, (match) => {
  const linkText = match[1];
  return `**[[${linkText}]]**`;
});
```

## Section & Block Controls

**INFO**

Targeted edits by heading or block for structured notes. These controls are essential for building applications that treat Markdown files like a database, allowing for stable modifications to specific parts of a document.

**Use when**

You need stable inserts into sections, block moves, or task toggles without manually parsing the entire file.

---

### `getSection`

**Description**

Retrieves the text content under a specific heading. It intelligently finds the start of the section and reads until it hits the next heading of the same or a higher level, or the end of the file.

**Signature**
```typescript
async function getSection(path: string, heading: string): Promise<string | null>
```

**Code**
```javascript
// A helper to escape regex special characters in a heading string.
function _escapeRegex(str) {
  return str.replace(/[.*+?^${}()|[\]\\]/g, r => `\\${r}`);
}

async function getSection(path, heading) {
  const text = await dc.readFile(path); // Assumes readFile helper is available
  if (text === null) return null;

  const re = new RegExp(`(^|\\n)(#+)\\s+${_escapeRegex(heading)}\\s*\\n`, 'i');
  const m = re.exec(text);
  if (!m) return null;

  const headingLevel = m[2].length;
  const start = m.index + m[0].length;
  const tail = text.slice(start);

  // Regex to find the next heading of the same or a higher level (fewer #s)
  const nextHeadingRe = new RegExp(`\\n#{1,${headingLevel}}\\s+`);
  const n = nextHeadingRe.exec(tail);
  const end = n ? start + n.index : text.length;

  return text.slice(start, end).trim();
}
```

**Usage Example**
```javascript
// Get the "Meeting Notes" section from a project file
const notes = await dc.getSection("Projects/Alpha/Status.md", "Meeting Notes");
if (notes) {
  console.log(notes);
}
```

---

### `setSection`

**Description**

Replaces the content of a section under a specific heading. If the heading does not exist in the file, it will be created at the end of the note.

**Signature**
```typescript
async function setSection(path: string, heading: string, body: string): Promise<void>
```

**Code**
```javascript
async function setSection(path, heading, body) {
  const text = await dc.readFile(path).catch(() => '');
  const hdr = `# ${heading}`;
  const re = new RegExp(`(^|\\n)(#+)\\s+${_escapeRegex(heading)}\\s*\\n`, 'i');
  const m = re.exec(text);

  if (!m) { // Heading doesn't exist, so append it
    const next = `${text}\n\n${hdr}\n\n${body.trim()}\n`.trim();
    await dc.writeFile(path, next);
    return;
  }

  const headingLevel = m[2].length;
  const start = m.index + m[0].length;
  const tail = text.slice(start);
  const nextHeadingRe = new RegExp(`\\n#{1,${headingLevel}}\\s+`);
  const n = nextHeadingRe.exec(tail);
  const end = n ? start + n.index : text.length;
  const next = `${text.slice(0, start)}${body.trim()}\n${text.slice(end)}`;
  await dc.writeFile(path, next);
}
```

**Usage Example**
```javascript
// Overwrite the 'Summary' section of a report
const newSummary = "The project is on track and meeting all KPIs.";
await dc.setSection("Reports/Q3-Summary.md", "Summary", newSummary);
```

### `toggleTask`

**Description**

Finds the first task line (`- [ ]`) that contains a specific substring and toggles its completion state.

**Signature**
```typescript
async function toggleTask(path: string, lineContains: string): Promise<void>
```

**Code**
```javascript
async function toggleTask(path, lineContains) {
  const text = await dc.readFile(path);
  if (!text) return;
  const lines = text.split('\n');
  const taskIndex = lines.findIndex(line => 
    line.includes(lineContains) && /- \[[ x]\]/.test(line)
  );

  if (taskIndex === -1) return;

  lines[taskIndex] = lines[taskIndex].includes('- [ ]') 
    ? lines[taskIndex].replace(/- \[ \]/, '- [x]') 
    : lines[taskIndex].replace(/- \[x\]/, '- [ ]');

  await dc.writeFile(path, lines.join('\n'));
}
```

**Usage Example**
```javascript
// Check off the "Submit report" task in a todo list
await dc.toggleTask("todo.md", "Submit report");
```

### `moveBlock`

**Description**

Moves a single line (a "block") identified by a matching substring from one file to another. This is the core logic used in the Kanban component.

**Signature**
```typescript
async function moveBlock(fromPath: string, toPath: string, lineContains: string): Promise<void>
```

**Code**
```javascript
async function moveBlock(fromPath, toPath, lineContains) {
  const fromText = await dc.readFile(fromPath);
  if (!fromText) return;

  const lines = fromText.split('\n');
  const i = lines.findIndex(l => l.includes(lineContains));
  if (i === -1) return; // Block not found in source file

  const blockToMove = lines[i];
  
  // Remove the block from the source file
  const nextFromText = lines.slice(0, i).concat(lines.slice(i + 1)).join('\n');
  await dc.writeFile(fromPath, nextFromText);
  
  // Append the block to the destination file
  await dc.appendFile(toPath, blockToMove); // Assumes appendFile helper
}
```

**Usage Example**
```javascript
// Move a task from the 'inbox' note to the 'today' note
await dc.moveBlock("inbox.md", "today.md", "Call the client");
```

## Metadata Controls

**INFO**

Controls for reading and modifying a note's YAML frontmatter. These functions use Obsidian's efficient caching and processing APIs to ensure high performance and data safety.

You would choose this direct, file-based approach over a Datacore query when your component needs to **target and modify a single, known file** in response to a direct user action (like clicking a "Mark as Complete" button on a specific task). A Datacore query is better suited for aggregating and displaying data from multiple notes at once.

**Use when**

Your application needs to store and manipulate structured metadata (like status, dates, or tags) separately from the main body text of a note.

---

### `getFrontmatter`

**Description**

Reads and parses the YAML frontmatter of a file. This function is highly efficient as it leverages Obsidian's built-in metadata cache, avoiding a full file read from disk whenever possible.

**Signature**
```typescript
async function getFrontmatter(path: string): Promise<object>
```

**Code**
```javascript
async function getFrontmatter(path) {
  const { TFile } = dc.obsidian;
  const file = dc.app.vault.getAbstractFileByPath(path);
  if (!file || !(file instanceof TFile)) {
    // Return empty object for non-existent files or folders
    return {};
  }
  const cache = dc.app.metadataCache.getFileCache(file);
  return cache?.frontmatter || {};
}
```

**Usage Example**
```javascript
// Get the status of a project note
const projectFm = await dc.getFrontmatter("Projects/Project Alpha.md");
if (projectFm.status === "active") {
  console.log("Project Alpha is currently active.");
}
```

---

### `updateFrontmatter`

**Description**

Safely updates or adds properties to a file's frontmatter. This is the recommended method for modifying frontmatter as it uses Obsidian's dedicated `processFrontMatter` API, which correctly handles creating the frontmatter block if it doesn't exist and preserves existing content.

**Signature**
```typescript
async function updateFrontmatter(path: string, patch: object): Promise<void>
```

**Code**
```javascript
async function updateFrontmatter(path, patch) {
  const { TFile } = dc.obsidian;
  const file = dc.app.vault.getAbstractFileByPath(path);
  if (!file || !(file instanceof TFile)) {
    throw new Error(`Datacore: File not found or is not a file: ${path}`);
  }

  await dc.app.fileManager.processFrontMatter(file, (fm) => {
    // This shallow merges the patch into the existing frontmatter (fm).
    Object.assign(fm, patch);
  });
}
```

**Usage Example**
```javascript
// Mark a project as complete and set a review date
const updates = {
  status: "complete",
  reviewed: new Date().toISOString().slice(0, 10)
};
await dc.updateFrontmatter("Projects/Project Alpha.md", updates);
new Notice("Project Alpha has been marked as complete.");
```

## Search & Index Controls

**INFO**

Lightweight discovery over vault files without using the full Datacore query engine.

You would choose this direct, file-based approach over a Datacore query when you need to perform simple, synchronous searches (like finding files in a folder), when you don't need the automatic reactivity of `dc.useQuery`, or for specific searches that the query language may not easily support (like complex glob patterns).

**Use when**

You need simple file lists, to find all notes with a specific tag, or to get the structural outline of a single note.

---

### `findByGlob`

**Description**

Finds files matching a simple glob pattern (e.g., `Journal/2024-*.md`). This provides a flexible way to find files by path without writing a complex regex.

**Signature**
```typescript
function findByGlob(glob: string): TFile[]
```

**Code**
```javascript
function findByGlob(glob) {
  // Converts a simple glob string into a case-insensitive regular expression.
  const re = new RegExp(
    `^${glob.replace(/[.*+?^${}()|[\]\\]/g, r => `\\${r}`).replace(/\*/g, '.*')}$`, 'i'
  );
  return dc.app.vault.getFiles().filter(f => re.test(f.path));
}
```

**Usage Example**
```javascript
// Find all daily notes from September 2024
const dailyNotesForSept = dc.findByGlob("Daily Notes/2024-09-*.md");
console.log(`Found ${dailyNotesForSept.length} notes for September.`);
```

---

### `findByTag`

**Description**

Finds all files containing a specific tag anywhere in the file (including frontmatter and body). This function is highly efficient as it uses Obsidian's optimized metadata cache.

**Signature**
```typescript
function findByTag(tag: string): TFile[]
```

**Code**
```javascript
function findByTag(tag) {
  const { TFile } = dc.obsidian;
  const searchTag = tag.startsWith('#') ? tag : `#${tag}`;
  const files = dc.app.vault.getMarkdownFiles();

  return files.filter(file => {
    const cache = dc.app.metadataCache.getFileCache(file);
    // getAllTags is a robust helper that gets tags from frontmatter and body
    const allTagsInFile = dc.obsidian.getAllTags(cache); 
    return allTagsInFile.includes(searchTag);
  });
}
```

### `findHeadings`

**Description**

Lists all Markdown headings from a given file. This is extremely fast as it reads directly from Obsidian's metadata cache, avoiding a full file read.

**Signature**
```typescript
function findHeadings(path: string): { heading: string, level: number }[] | null
```

**Code**
```javascript
function findHeadings(path) {

  const file = dc.app.vault.getAbstractFileByPath(path);

  const cache = dc.app.metadataCache.getFileCache(file);
  // The cache stores headings with their text and level (1-6)
  return cache?.headings?.map(h => ({ heading: h.heading, level: h.level })) || [];
}
```

// Generate a simple table of contents for a long note
const headings = dc.findHeadings("My Long Document.md");

## Asset Controls

**INFO**

Controls for turning local files in your vault into browser-usable URLs. This is the essential bridge between your vault's assets and web-based rendering technologies like `<img>` tags, video players, and 3D engines.

**Use when**

You need to render images, play audio or video, or load 3D models and textures from files stored directly in your vault.

---

### `resolveAssetUrl`

**Description**

The primary and most direct way to get a playable or renderable URL for a file when you know its exact vault path. It returns the special `obsidian://` resource path.

**Signature**
```typescript
function resolveAssetUrl(path: string): string | null
```

**Code**
```javascript
function resolveAssetUrl(path) {
  const { TFile, normalizePath } = dc.obsidian;
  const file = dc.app.vault.getAbstractFileByPath(normalizePath(path));
  
  if (!file || !(file instanceof TFile)) {
    console.error(`Asset not found or is not a file: ${path}`);
    return null;
  }
  return dc.app.vault.getResourcePath(file);
}
```

**Usage Example**
```javascript
// Get the URL for a background music track to use in an <audio> element
const songPath = "_RESOURCES/MUSIC/beto.minigame.soundtrack.wav";
const audioSrc = dc.resolveAssetUrl(songPath);

if (audioSrc) {
  return <audio src={audioSrc} controls />;
}
```

---

### `blobUrlForPath`

**Description**

Creates a temporary `blob:` URL from a file's binary content. This is useful for generating immediate previews of images, especially those selected by a user or uploaded, without relying on the `obsidian://` protocol. **Important:** To prevent memory leaks, you must release this URL when your component unmounts using `URL.revokeObjectURL(url)`.

**Signature**
```typescript
async function blobUrlForPath(path: string): Promise<string | null>
```

**Code**
```javascript
async function blobUrlForPath(path) {
  const { TFile, normalizePath } = dc.obsidian;
  const file = dc.app.vault.getAbstractFileByPath(normalizePath(path));

  if (!file || !(file instanceof TFile)) return null;
  
  const binaryContent = await dc.app.vault.readBinary(file);
  const blob = new Blob([binaryContent]);
  return URL.createObjectURL(blob);
}
```

**Usage Example**
```javascript
const { useState, useEffect } = dc;

function ImagePreview({ imagePath }) {
  const [previewUrl, setPreviewUrl] = useState(null);

  useEffect(() => {
    let url;
    async function loadPreview() {
      url = await dc.blobUrlForPath(imagePath);
      setPreviewUrl(url);
    }
    loadPreview();
    
    // Cleanup function to prevent memory leaks
    return () => {
      if (url) URL.revokeObjectURL(url);
    };
  }, [imagePath]);

  return previewUrl ? <img src={previewUrl} /> : <div>Loading preview...</div>;
}
```


## State Persistence Controls

**INFO**

A simple, robust, key-value store for saving a component's state as a JSON file. This system automatically manages files in a hidden `.datacore/state` directory, providing a clean way to add persistence.

You would choose this approach over storing state in a Markdown file's frontmatter when the data is not meant for direct user editing (e.g., UI settings, internal history, game progress) and you want to avoid cluttering user-facing notes.

**Use when**

You need to reliably persist data that is essential to your component's function across Obsidian sessions, such as:

*   **User Settings & Configuration**: API keys, theme choices, or default values.
*   **Application State & Progress**: The current state of a game or a complex workflow.
*   **Session History**: Chat logs, playlists, or a history of user actions.

---

### Core Controls

These are the fundamental functions for managing data in the `.datacore` directory. They are designed to be used together to create a seamless load/save experience.

#### `statePath`

**Description**

A simple utility that returns a standardized, consistent file path for a given persistence key.

**Signature**
```typescript
function statePath(key: string): string
```

#### `loadState`

**Description**

Asynchronously loads and parses a JSON state file. If the file doesn't exist or is invalid, it will automatically call `saveState` to write the provided `defaults` to disk, ensuring a valid state is always returned.

**Signature**
```typescript
async function loadState<T>(key: string, defaults: T): Promise<T>
```

#### `saveState`

**Description**

Asynchronously serializes a JavaScript object to a nicely formatted JSON string and saves it to the appropriate state file, creating the `.datacore/state` directory if it doesn't exist.

**Signature**
```typescript
async function saveState<T>(key: string, value: T): Promise<void>
```

**Code**
```javascript
// Directory for all persisted component state
const STATE_DIR = ".datacore/state";

function statePath(key) {
  return `${STATE_DIR}/${key}.json`;
}

async function loadState(key, defaults) {
  const path = statePath(key);
  try {
    const raw = await dc.app.vault.adapter.read(path);
    return JSON.parse(raw);
  } catch (e) {
    // If reading fails, save the default state for next time
    await saveState(key, defaults);
    return defaults;
  }
}

async function saveState(key, value) {
  await dc.ensureFolder(STATE_DIR); // Assumes ensureFolder helper
  const path = statePath(key);
  const json = JSON.stringify(value, null, 2);
  await dc.app.vault.adapter.write(path, json);
}
```

**Usage Example: Persisting a Component's State**

This is the most common pattern for using these controls. A `useEffect` hook loads the state on mount, and another saves the state whenever it changes.

```jsx
const { useState, useEffect } = dc;
const SETTINGS_KEY = "my-component/user-settings";

function SettingsComponent() {
  // State for UI, initialized with a default
  const [name, setName] = useState("Loading...");
  const [isLoaded, setIsLoaded] = useState(false);

  // 1. Load state from vault on initial render
  useEffect(() => {
    async function loadSettings() {
      const savedState = await dc.loadState(SETTINGS_KEY, { userName: "" });
      setName(savedState.userName);
      setIsLoaded(true);
    }
    loadSettings();
  }, []); // Empty array ensures this runs only once

  // 2. Save state whenever 'name' changes (after the initial load)
  useEffect(() => {
    if (isLoaded) { // Prevent saving during the initial load
      dc.saveState(SETTINGS_KEY, { userName: name });
    }
  }, [name, isLoaded]);

  if (!isLoaded) return <div>Loading settings...</div>;

  return (
    <div>
      <label>Your Name:</label>
      <input 
        type="text" 
        value={name} 
        onChange={(e) => setName(e.target.value)} 
      />
      <p>Hello, {name || 'stranger'}!</p>
    </div>
  );
}
```

## Transaction & Backup Controls

**INFO**

Safety wrappers for critical or complex file writes. These controls help prevent accidental data loss during multi-step modifications or when performing risky operations.

**Use when**

You are performing complex edits where data corruption is a risk, or when handling critical user data that should be backed up before modification.

---

### `withBackup`

**Description**

Performs a function that modifies a file's content, but only after creating a timestamped backup of the original file. Backups are stored in a hidden `.datacore/backups` directory, mirroring the vault's folder structure.

**Signature**
```typescript
async function withBackup(
  path: string, 
  modifyFn: (currentContent: string) => Promise<string> | string
): Promise<void>
```

**Code**
```javascript
async function withBackup(path, modifyFn) {
  const currentContent = await dc.readFile(path).catch(() => '');
  
  // Create a timestamp string like '20240902-143000'
  const ts = new Date().toISOString().replace(/[:.]/g, '-');
  
  const backupParentDir = `.datacore/backups/${path}`.split('/').slice(0, -1).join('/');
  await dc.ensureFolder(backupParentDir); // Assumes ensureFolder helper

  const backupPath = `${backupParentDir}/${path.split('/').pop()}.${ts}.bak`;
  await dc.writeFile(backupPath, currentContent); // Assumes writeFile helper
  
  const nextContent = await modifyFn(currentContent);
  await dc.writeFile(path, nextContent);
}
```

**Usage Example**
```javascript
// Safely refactor a note by replacing all occurrences of a word
const refactorNote = async (notePath) => {
  await dc.withBackup(notePath, (content) => {
    // This function receives the current content and returns the new content
    return content.replace(/OldProjectName/g, "NewProjectName");
  });
  new Notice("Note refactored with a backup created.");
};
```

---

### `batchApplyEdits`

**Description**

Applies multiple, precise text edits to a single file as one atomic operation, wrapped with the `withBackup` control for maximum safety. This is ideal for complex, programmatic refactoring of a document.

**Signature**
```typescript
type TextEdit = { from: number; to: number; text: string };
async function batchApplyEdits(path: string, edits: TextEdit[]): Promise<void>
```

**Code**
```javascript
async function batchApplyEdits(path, edits) {
  // This control is a practical application of withBackup and applyEdits
  await dc.withBackup(path, async (currentContent) => {
    let content = currentContent;
    // Apply edits from the end to the start to preserve indices
    const sorted = [...edits].sort((a, b) => b.from - a.from);
    
    for (const e of sorted) {
      content = content.slice(0, e.from) + e.text + content.slice(e.to);
    }
    return content;
  });
}
```

**Usage Example**
```javascript
// Perform a complex, multi-point edit on a file safely
const edits = [
  { from: 10, to: 15, text: "new text A" },
  { from: 100, to: 110, text: "new text B" }
];
await dc.batchApplyEdits("MyDocument.md", edits);
```

## Template Controls

**INFO**

Controls for rendering simple templates with variables and writing the output to files.

**Use when**

You need to programmatically create new notes from a pre-defined structure or insert boilerplate content that includes dynamic values like dates or user input.

---

### `renderTemplate`

**Description**

A simple template renderer that takes a template string and an object of variables. It replaces all occurrences of `{{variableName}}` placeholders in the string with their corresponding values. If a variable is not found, the placeholder is kept in the output string.

**Signature**
```typescript
function renderTemplate(template: string, variables: Record<string, string | number>): string
```

**Code**
```javascript
function renderTemplate(template, variables) {
  // Regex finds {{ variable.name }} style placeholders, ignoring whitespace.
  return template.replace(/{{\s*([\w.-]+)\s*}}/g, (_, key) => {
    // Return the variable's value, or the original placeholder if not found.
    return String(variables[key] ?? `{{${key}}}`);
  });
}
```

**Usage Example**
```javascript
const template = "# Meeting Notes: {{title}}\n\nDate: {{date}}\n\n## Attendees\n- {{attendee}}";
const variables = {
  title: "Q4 Planning",
  date: new Date().toISOString().slice(0, 10),
  attendee: "Alice"
};

const renderedContent = dc.renderTemplate(template, variables);
console.log(renderedContent);
// Output:
// # Meeting Notes: Q4 Planning
//
// Date: 2024-09-02
//
// ## Attendees
// - Alice
```

---

### `renderToFile`

**Description**

A convenience wrapper that combines `renderTemplate` and `writeFile`. It renders a template with the given variables and writes the final content directly to a specified file path.

**Signature**
```typescript
async function renderToFile(path: string, template: string, variables: Record<string, string | number>): Promise<void>
```

**Code**
```javascript
async function renderToFile(path, template, variables) {
  // Assumes renderTemplate and writeFile helpers are available
  const output = dc.renderTemplate(template, variables);
  await dc.writeFile(path, output);
}
```

**Usage Example**
```javascript
// Create a new daily note from a template
const dailyTemplate = "---\ntags: [daily-note]\n---\n\n# Daily Note for {{date}}";

```

*   **Comprehensive Application State (Settings, History, and Content)**
    *   **[[CHATLLM]]**: This is the most extensive example. It uses a single `saveState` call to persist its entire, complex state object. This includes:
        *   **User Configuration**: All provider settings, API keys, and model parameters.
        *   **Session History**: The full transcript of every chat conversation.
        *   **UI State**: The currently active chat and other UI settings.
    This approach treats the JSON file as a complete snapshot of the application, ensuring a seamless experience across reloads.

*   **User-Generated Content & Layout State**
    *   **[[CANVAS v2]]**: Uses state persistence to save the entire creative output of the user. `saveState` is used to store a large JSON object containing the properties of every shape, text box, and embedded component, as well as the canvas's current pan and zoom coordinates.

*   **Game Progress & Session State**
    *   **[[CARD PICKER]]**: Implements a classic "save on exit" feature. After every card draw, `saveState` is called to update a JSON file with the remaining cards in the deck, the history of drawn cards, and the current score. `loadState` on initialization picks the game up exactly where the user left off.

*   **User Preferences & Collections**
    *   **[[MUSIC PLAYER]] / [[MOBILE MUSIC PLAYER]]**: This component uses state persistence to manage a user's collection of "liked" songs. It calls `saveState` to write a simple dictionary of track IDs to `liked-songs.json`, separating personal preferences from the ephemeral state of the playlist.

*   **Application Data & Versioning (Advanced Use Case)**
    *   **[[CODE EDITOR v2]]**: While not for UI state, it cleverly adapts this pattern for its version control system. Each "commit" is a snapshot of the code's state at a point in time. It uses logic equivalent to `saveState` to write these commit objects as individual JSON files to a hidden `.datacore` directory.
