## Live Queries

**What it is**

The primary method for fetching structured, reactive data from notes across the vault. These controls allow components to subscribe to data changes and automatically update.

**Use when**

You need to create live dashboards, dynamic tables, or any UI that must stay in sync with the content of your notes.

### `useQuery`

A reactive React hook that runs a Datacore query and automatically re-renders your component when the underlying data changes.

```jsx
// --- In a ViewComponent ---
const { useState } = dc;

function RecentTasksList() {
  // Query for tasks in the 'Projects' folder, newest first.
  const query = `@task and path("Projects") order by $ctime desc limit 50`;
  const tasks = dc.useQuery(query);

  if (!tasks) return <div>Loading tasks...</div>;

  return (
    <ul>
      {tasks.map(task => (
        <li key={task.$path}>{task.text}</li>
      ))}
    </ul>
  );
}
```

### `api.query`

A one-shot, asynchronous function to execute a query. It does not automatically update and is best for background tasks or non-React contexts.

```jsx
// --- In an async helper function ---
async function countUrgentTasks() {
  const query = `@task and #urgent`;
  try {
    const urgentTasks = await dc.api.query(query);
    new Notice(`You have ${urgentTasks.length} urgent tasks.`);
  } catch (e) {
    console.error("Failed to run query:", e);
    new Notice("Error counting tasks.");
  }
}
```

## Data Accessors

**What it is**

Standard methods for accessing properties on the objects returned by Datacore queries. This includes both built-in note metadata and custom frontmatter fields.

**Use when**

You have a query result and need to display specific pieces of information from each note, task, or item.

### Accessing Note Properties

Datacore query results have special `$`-prefixed properties for core metadata.

```jsx
// --- Inside a component using a query result item ---
function NoteInfo({ note }) {
  const name = note.$name || "Untitled";
  const path = note.$path;
  const created = note.$ctime.toFormat("yyyy-MM-dd");
  const tags = (note.$tags || []).join(', ');

  return (
    <div>
      <h3>{name} ({path})</h3>
      <p>Created: {created}</p>
      <p>Tags: {tags}</p>
    </div>
  );
}
```

### Accessing Frontmatter Fields

Frontmatter fields are available as direct properties on the query result object.

```jsx
// --- Inside a component using a query result item ---
function BookInfo({ bookNote }) {
  // Assumes frontmatter like:
  // ---
  // author: "Jane Doe"
  // rating: 5
  // ---
  const author = bookNote.author || "Unknown Author";
  const rating = bookNote.rating || "Not Rated";

  return <p>{bookNote.$name} by {author} ({rating} stars)</p>;
}
```

## Markdown Parsing

**What it is**

Controls for breaking down the raw text content of a single file into a structured format.

**Use when**

A note's structure is defined by separators (like `---`) or headings, and you need to treat each section as a distinct item.

### Splitting Content by Separator

A common pattern for creating "cards" or "sections" from a single note using a horizontal rule (`---`) as a delimiter.

```jsx
function parseContentToSections(content) {
  // Splits by '---' on its own line, filtering out empty sections.
  const sections = content
    .split(/^\s*-{3,}\s*$/m)
    .map(s => s.trim())
    .filter(s => s);
  return sections;
}
```

## Vault Searching

**What it is**

Controls for finding files across the entire vault, especially non-Markdown assets, without needing an exact path.

**Use when**

You need to locate an image, video, or animation by its filename, with tolerance for typos.

### Fuzzy Finding Files

Uses the Fuse.js library to find a file by its name with typo tolerance.

```jsx
// Requires the Fuse.js library to be loaded.
async function fuzzyFindFile(filename) {
  if (!window.Fuse) {
    // A simple script loader; see Module 5 for advanced caching.
    await new Promise(res => {
      const s = document.createElement("script");
      s.src = "https://cdn.jsdelivr.net/npm/fuse.js/dist/fuse.js";
      s.onload = res;
      document.body.appendChild(s);
    });
  }

  const files = dc.app.vault.getFiles();
  const fuse = new Fuse(files, { keys: ["name"], threshold: 0.4 });
  const results = fuse.search(filename);
  return results.length > 0 ? results[0].item : null;
}
```

## Ship It: Minimal Starter Flow

1.  Use `dc.useQuery` to fetch a live list of notes or tasks.
2.  Map over the results and use **Data Accessors** like `item.$name` and `item.dueDate` to display the information.
3.  For a component that renders an image, use `fuzzyFindFile` to locate the asset first.
4.  For components that need to show content from a note structured with `---`, use `parseContentToSections` to get an array of items to display.

# Data & Query Layer: Functional Patterns & Examples

This module is the core data engine of the framework. It provides developers with powerful tools to fetch, filter, parse, and search for data within the Obsidian vault. The functionalities are broken down into distinct patterns, each serving a specific development need.

---

### 1. Live, Reactive Queries on Vault Data

**What it does:** This is the primary pattern for fetching structured data from notes. It allows components to perform real-time, reactive queries that automatically update the UI whenever the underlying vault data changes. If a note is modified to match (or no longer match) a query's criteria, the component using that query will re-render with the new data set.

**Key API Functions:**

- dc.useQuery(queryString)
    

**When to Use It:**

- To create live dashboards that reflect the current state of your notes.
    
- To build dynamic tables, lists, or galleries that are always up-to-date.
    
- Whenever your component needs to display a collection of notes based on folder, tags, or frontmatter properties.
    
- For any feature that needs to react to file changes, creations, or deletions without manual refreshing.
    

**Examples in Practice:**

- **Dynamic Datacore View / Recipe Viewer** (.../0 DATACORE.flexilis/): This component is a masterclass in dc.useQuery. It fetches all pages from a user-specified path (@page and path("${queryPath}")), then allows for live filtering, sorting, and grouping of the results. Every time a recipe note is updated, the table view reflects the changes instantly.
    
- **Tag Browser** (.../4 TagViewer/): The foundation of this component is a broad query (dc.useQuery("@page")) that fetches every page in the vault. The component then processes this live data in memory to build its hierarchical tag structure. If you re-tag a note anywhere in your vault, the browser's structure updates automatically.
    
- **Basic Query** (.../2 BasicQuery/): As the name implies, this is a straightforward implementation. It uses dc.useQuery with a dynamic query string to show a simple, paginated table of notes from a user-defined folder.
    
- **Kanban Board** (.../10 Kanban/): Uses a targeted query (@page and $name = "${exactName}") to find the specific Markdown files that represent the board's columns. The results from this query are then parsed to create the cards.
    
- **License Agreement** (.../26 LicenseAgreement/): Employs a highly specific query (@task and ($file = "${escapedTargetFileNameOnly}"...)) to find only the checkbox tasks within a single, specific note. The UI is then rendered based on the completion status of these live-queried tasks.
    
- **Receipt Tracker** (.../43 ReceiptTracker/): In its DashboardView, it uses Datacore queries (likely on the _Processed folder) to gather all processed receipt data and generate analytics and charts.
    

---

### 2. Single-File Content Parsing

**What it does:** This pattern involves taking the raw text content of a single Markdown file and breaking it down into a structured, usable format. This is often done after a file has been identified by a query or other means. The key is turning a block of text into an array of sections, objects, or other data structures.

**Key API Functions:**

- parseMarkdown(src) (The formal API)
    
- Custom Implementations: Many components use custom string splitting (e.g., content.split(/(\n\s*-{3,}\s*\n)/m)) to achieve similar results tailored to a specific format.
    

**When to Use It:**

- When a note's structure is defined by separators like horizontal rules (---) or headings.
    
- To create a "feed" or "carousel" where each section of a note is an item.
    
- For building UIs like Kanban boards where each "card" is a chunk of text between separators.
    

**Examples in Practice:**

- **Kanban Board** (.../10 Kanban/): After querying for the column files, the parseFileContent function is used. It splits the entire file's content by a --- separator to create an array of strings, where each string becomes the content for a card.
    
- **Custom Feed / Iframe Player** (.../5 CustomFeed/, .../19 IframePlayer/): The FileSectionsProvider is a dedicated utility for this pattern. It reads a Markdown file and splits its content by --- separators to create a navigable feed of sections, each of which can contain an embeddable URL.
    
- **Bounty View** (.../7 BountyView/): This component parses a .namzu file (a specific Markdown format) to find level-6 headers (######). Each header and its associated content is treated as a distinct "node" to be displayed in its radial graph visualization.
    

---

### 3. Fuzzy Vault Search for Assets

**What it does:** This pattern uses a typo-tolerant search to find a file anywhere in the vault based on its name, without needing the exact path. It is most useful for locating non-Markdown assets like images, videos, or animations when the user might only remember part of the filename.

**Key API Functions:**

- fuzzyFind(q, opts)
    
- Legacy/Custom Implementation: Several components implement this directly using the Fuse.js library over the vault's file list (app.vault.getFiles()).
    

**When to Use It:**

- When you need to let a user find an image or media file without navigating the folder structure.
    
- To create robust media viewers where the exact path to an asset might change.
    
- For linking to assets in your code by a memorable name rather than a brittle, hardcoded path.
    

**Examples in Practice:**

- **Image Render** & **Aquarium** (.../11 ImageRender/, .../13 Aquarium/): Both components have hardcoded filenames for assets they need to display (e.g., an image or a Lottie background). They use a fuzzyFindFile helper function, which runs a Fuse.js search on all vault files to locate the asset, making the component work even if the user moves the asset file.
    
- **Lottie Experiment** (.../12 LottieExperiment/): Explicitly uses fuzzyFindFile to locate "obsidian_lottie.json" and "test.json", demonstrating its ability to find specific, non-Markdown files by name for rendering.
