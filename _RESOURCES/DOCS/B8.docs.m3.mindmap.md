


# UI & Interaction Patterns: Functional Patterns & Examples

This module provides a suite of reusable components and hooks for building rich, interactive user interfaces. These patterns handle complex tasks like rendering large datasets, managing drag-and-drop interactions, and creating sophisticated navigation structures, ensuring a consistent and high-performance user experience.

---

### 1. High-Performance Data Tables & Lists

**What it does:** This pattern involves rendering structured data (typically from a dc.useQuery result) into a dynamic, feature-rich table or list. These components are designed for performance, capable of handling thousands of rows smoothly through virtualization. They often include built-in functionalities like customizable columns, pagination, grouping, and in-place editing.

**Key API Primitives:**

- <DataTable rows={...} columns={...} />
    
- Custom-built table structures using standard HTML (<div>, <table>) combined with Datacore state management (dc.useState).
    

**When to Use It:**

- For creating dashboards that display query results in a tabular format.
    
- When you need to display and allow user interaction with large datasets (hundreds or thousands of items) without performance degradation.
    
- For building UIs that require features like column reordering, dynamic column creation, pagination, or grouping by a specific data field.
    

**Examples in Practice:**

- **Dynamic Datacore View / Recipe Viewer** (.../0 DATACORE.flexilis/): This is the quintessential example. It constructs a highly interactive table from scratch using <div> elements.
    
    - **Data Source:** Live data from dc.useQuery.
        
    - **Features:**
        
        - **Customizable Columns:** Users can add, remove, rename, and reorder columns through a dedicated "Edit Headers" interface. The mapping between a column header (e.g., "Creation Date") and a data property (e.g., ctime.obsidian) is fully dynamic.
            
        - **Grouping:** Allows users to group the entire dataset by the values in any column (e.g., group all recipes by genre).
            
        - **Pagination:** Implements client-side pagination to manage large result sets, showing a fixed number of items per page with controls to navigate.
            
        - **Filtering:** A text input filters the entire dataset in real-time.
            
- **ActivityWatchDashboard** (.../35 ActivityWatchDashboard/): In its "Detailed View," this component renders a paginated list of all recorded application events. This demonstrates how to present a large, time-series dataset in a manageable, browsable format.
    
- **Receipt Tracker** (.../43 ReceiptTracker/): The "Processed Summary" panel displays a table of all parsed receipts. It includes columns for the filename, merchant, date, and total amount, showcasing a clear, summary-style data table. It also includes action buttons within each row for editing or viewing the source image.
    
- **Basic Query** (.../2 BasicQuery/): While simpler, this component uses the core table pattern to display notes from a folder path with sortable columns for name, creation time, modification time, and tags.

### 2. Drag & Drop System

**What it does:** This pattern enables users to physically move UI elements around the screen to trigger actions or reorder data. This can range from dragging items between lists (like Kanban cards), reordering columns in a table, or dragging a data object (like a note link) out of the component and into the main Obsidian editor.

**Key API Hooks & Event Handlers:**

- useDrag(type, data) / useDrop(accept, onDrop) (Formal API)
    
- Manual implementation using HTML5 Drag and Drop API attributes: draggable, onDragStart, onDrop, onDragOver.
    

**When to Use It:**

- To allow users to reorder items in a list or columns in a table.
    
- For creating Kanban-style boards where cards are moved between columns.
    
- To enable "drag-out" functionality, where data from your component can be dropped into an Obsidian note to create a link or embed content.
    
- For any UI that mimics physical interaction with objects, such as moving items on a canvas or in a 3D world.
    

**Examples in Practice:**

- **Kanban Board** (.../10 Kanban/): Implements a complete drag-and-drop system for both cards and columns (lanes).
    
    - **Cards:** Each card (EditableItem) is marked as draggable and its onDragStart handler attaches the itemId to the data transfer object.
        
    - **Columns:** Each column (Lane) has onDragOver and onDrop handlers. The onDrop handler reads the itemId, identifies the source and target columns, and then triggers file system operations to move the card's text from one note to another.
        
    - **Columns Reordering:** The columns themselves are draggable to allow the user to reorder the board layout.
        
- **Dynamic Datacore View / Recipe Viewer** (.../0 DATACORE.flexilis/):
    
    - **Column Reordering:** The DraggableEditBlock component, which appears in the "Edit Headers" mode, is draggable. Its onDragStart and onDrop handlers manipulate the columnsToShow state array to reorder the columns in the main table.
        
    - **Draggable Note Links:** The DraggableLink component makes the recipe name in each row draggable. The onDragStart handler sets the data to a standard Obsidian wikilink format ([[Recipe Name]]), allowing the user to drag a link to any recipe directly into another note.
        
- **Tag Browser** (.../4 TagViewer/): Similar to the Recipe Viewer, both tags and notes within the browser are draggable. The onDragStart handler populates the data transfer with either a tag (#path/to/tag) or a wikilink ([[Note Name]]), making the browser a powerful tool for populating other notes.

### 3. Hierarchical Navigation

**What it does:** This pattern provides UI elements for navigating through nested or tree-like data structures. This is most commonly visualized as an expandable tree view, a "breadcrumb" trail that shows the current path, or a view where clicking an item "drills down" into a deeper level of the hierarchy.

**Key API Primitives:**

- <TreeNav nodes={...} />
    
- Custom-built navigation logic using state (e.g., dc.useState([]) to hold the path array) and UI elements that modify that state.
    

**When to Use It:**

- For file explorers or folder navigators.
    
- To create a browser for nested tags (e.g., parent/child/grandchild).
    
- In any application where the data has a clear parent-child relationship and you want the user to be able to explore it level by level.
    

**Examples in Practice:**

- **Tag Browser** (.../4 TagViewer/): This is the primary example of this pattern. It processes a flat list of all tags in the vault and builds a hierarchical tree based on / delimiters.
    
    - **State Management:** It uses a currentPath state array (e.g., ['projects', 'active']) to track the user's location in the tag hierarchy.
        
    - **Drill-Down:** Clicking a tag item appends its key to the currentPath array, causing the component to re-render and display the children of that tag.
        
    - **Breadcrumbs & Back Navigation:** A breadcrumb trail is rendered from the currentPath array, allowing the user to jump back to any parent level. A "Back" button simply pops the last item off the currentPath array.
        
- **Bounty View** (.../7 BountyView/): While its visualization is a radial graph, the underlying interaction is hierarchical. The component displays headers from a single file as nodes. Clicking a node that represents a link to another file effectively navigates "down" into that file, loading it as the new central node. The "Home" button serves to navigate back "up" to the root file.
