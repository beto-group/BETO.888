This module provides the patterns and tools for connecting Datacore components to external services. This includes integrating with powerful AI models, leveraging the capabilities of other Obsidian plugins, and communicating with web services both on the local machine and on the internet.

## External API Controls

**What it is**

Controls for communicating with remote web servers over the internet. This is the foundation for integrating any third-party service that exposes an HTTP API.

**Use when**

You need to fetch data from an external source, send data to a webhook, or connect to a cloud-based AI provider.

### fetchApi

A robust wrapper for making web requests using Obsidian's requestUrl. It handles JSON parsing and basic error checking, simplifying API calls.

    ``async function fetchApi(url, options = {}) {   const requestUrl = dc.app.requestUrl || window.requestUrl;   if (!requestUrl) throw new Error("Datacore's requestUrl is not available.");    const response = await requestUrl({      url,      method: options.method || 'GET',     ...options    });    if (response.status !== 200) {     throw new Error(`Request failed, status ${response.status} for ${url}`);   }   return JSON.parse(response.text); }``

    ``async function callGroqLLM(apiKey, promptText) {   const GROQ_API_URL = "https://api.groq.com/openai/v1/chat/completions";   const GROQ_MODEL = "llama3-8b-8192";   const requestUrl = dc.app.requestUrl;    const payload = {     model: GROQ_MODEL,     messages: [ { role: "user", content: promptText } ],     temperature: 0.1,     response_format: { type: "json_object" },   };    const response = await requestUrl({     url: GROQ_API_URL, method: "POST",     headers: { "Content-Type": "application/json", "Authorization": `Bearer ${apiKey}` },     body: JSON.stringify(payload),   });    return JSON.parse(JSON.parse(response.text).choices[0].message.content); }``
  

### Serverless Webhook

A fire-and-forget request to a remote endpoint, such as a serverless function. It uses mode: 'no-cors' which allows sending data without complex CORS configurations, but prevents reading the response.

## Local Service Controls

**What it is**

Controls for communicating with services running on the user's own machine, including other applications or plugins within Obsidian.

**Use when**

You need to build a dashboard for a local productivity tool or create a workflow that combines the functionality of multiple plugins.

### Localhost API

Fetching data from a web server running locally (e.g., on localhost:5600). This is identical to using fetchApi but with a local URL.

    ``async function getActivityWatchData() {   const AW_URL = "http://localhost:5600/api/0/query";   const requestUrl = dc.app.requestUrl;      const query = `     aw_events = query_bucket("aw-watcher-window_localhost.localdomain");     RETURN = aw_events;   `;    try {     const response = await requestUrl({       url: AW_URL, method: 'POST',       contentType: 'application/json',       body: JSON.stringify({ query }),     });     return JSON.parse(response.text);   } catch (e) {     new Notice("ActivityWatch server not running or unreachable.", 5000);     return null;   } }``

## Ship It: Minimal Starter Flow

1. To get data from the web, copy the **fetchApi** helper into your component.
    
2. To build an AI feature, use the **callGroqLLM** pattern, ensuring you have a way for the user to provide their API key.
    
3. To integrate with a local app like ActivityWatch, use the **getActivityWatchData** pattern.
    
4. To build a workflow with another plugin, use the **getTextExtractorApi** pattern as a template, replacing 'text-extractor' with the ID of the target plugin.
