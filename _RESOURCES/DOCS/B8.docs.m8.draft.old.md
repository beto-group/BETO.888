## Modular Loading

**What it is**

Controls for dynamically importing sub-components, helper functions, or configuration modules from other Markdown files at runtime.

**Use when**

You need to break a large application into smaller, manageable, and reusable pieces of code, or when you want to share utility functions across multiple components.

### `dc.require`

Dynamically loads a JavaScript module from another file. This is the cornerstone of building composite applications. The target code block must end with a `return` statement.

```jsx
// --- In your main ViewComponent ---
const { useState, useEffect } = dc;

function MyAppComponent() {
  const [MySubComponent, setMySubComponent] = useState(null);

  useEffect(() => {
    // Path to the markdown file containing the sub-component
    const subComponentPath = "path/to/MySubComponent.md";
    
    dc.require(subComponentPath)
      .then(module => setMySubComponent(() => module.View))
      .catch(err => console.error("Failed to load sub-component:", err));
  }, []);

  if (!MySubComponent) return <div>Loading modules...</div>;

  return <MySubComponent />;
}
```

### `dc.headerLink`

A helper function that creates a robust, unambiguous link to a specific header block within another file. This is the **recommended way** to target code blocks for `dc.require`.

```jsx
// --- Inside any component file ---

// In this file: MyMainComponent.md
async function loadHelpers() {
  // Target the # ViewComponent block inside another file
  const utilityPath = dc.headerLink(
    "path/to/MyUtilities.md",
    "ViewComponent"
  );

  const { MyUtilityFunction } = await dc.require(utilityPath);
  MyUtilityFunction();
}
```

## Application Flow

**What it is**

Patterns for orchestrating and managing the state of multiple child components to create a cohesive application experience.

**Use when**

Your application has multiple distinct screens or modes (e.g., a "list view" vs. a "detail view") and you need to control the flow of data between them.

### Controller Component

A main "controller" component that manages which child view is currently active and passes data down to it. This is the primary pattern for building multi-screen applications.

```jsx
// --- Main ViewComponent acting as a controller ---
const { useState, useEffect } = dc;

function AppController() {
  const [currentView, setCurrentView] = useState('list'); // 'list' or 'detail'
  const [selectedItemId, setSelectedItemId] = useState(null);
  
  // Dynamically load the child view components
  const [ListView, setListView] = useState(null);
  const [DetailView, setDetailView] = useState(null);
  useEffect(() => {
    dc.require("path/to/ListView.md").then(m => setListView(() => m.View));
    dc.require("path/to/DetailView.md").then(m => setDetailView(() => m.View));
  }, []);

  const handleSelect = (itemId) => {
    setSelectedItemId(itemId);
    setCurrentView('detail');
  };

  const handleBack = () => setCurrentView('list');

  if (!ListView || !DetailView) return "Loading views...";

  if (currentView === 'list') {
    return <ListView onSelectItem={handleSelect} />;
  } else {
    return <DetailView itemId={selectedItemId} onBack={handleBack} />;
  }
}
```

## State Management

**What it is**

Controls for managing the internal state of your components, such as user input, UI toggles, and fetched data.

**Use when**

You need your component to be interactive and remember information across re-renders.

### `useState` for Local State

The fundamental hook for adding state to a component. When the state is updated, the component re-renders. This state is local to the component instance and is lost when the component unmounts.

```jsx
// --- Inside any ViewComponent ---
const { useState } = dc;

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(currentCount => currentCount + 1)}>
        Increment
      </button>
    </div>
  );
}
```

## Ship It: Minimal Starter Flow

1.  Break down your application into logical UI pieces (e.g., `ListView.md`, `DetailView.md`). Place the component code for each in a `# ViewComponent` block that `return`s the component function.
2.  Create a main `AppController.md` file. Use **`dc.require`** and **`dc.headerLink`** inside a `useEffect` to load your child view components into state.
3.  Use **`dc.useState`** in the controller to keep track of the `currentView` and any shared data.
4.  Conditionally render the active child component, passing down any necessary data and callback functions as props. This completes the **Controller Component** pattern.
