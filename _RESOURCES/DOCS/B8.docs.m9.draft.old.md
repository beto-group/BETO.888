# Module 9 — Immersive Control & Input Management: Catalog & Applications (Final Draft)

This module provides the advanced controls for creating focused, game-like, or modal experiences. The core pattern involves temporarily capturing and overriding Obsidian's default input handling, ensuring that user actions like keyboard presses and mouse movements are directed exclusively to the component, not to the wider application.

## Controls Catalog (Outline)

*   **Input Capture & Blocking**

    *   Pointer Lock: Capturing the mouse for first-person camera controls.
*   **Scoped Input Handling**
    *   Component-Level Key Listeners: Handling keyboard input only when the component is active.

## Input Capture & Blocking

**What it is**

Controls for taking exclusive ownership of user input. This is the most critical pattern for creating immersive applications that need to prevent conflicts with Obsidian's native shortcuts.

**Use when**

You are building a game, a 3D world, a modal dialog, or any component where keys like `Cmd/Ctrl+W`, `WASD`, or `Space` must control your component, not Obsidian.

### `useInputBlocker`

A comprehensive hook that manages focus on your component's container. When the component is focused, it automatically disables nearly all of Obsidian's commands and hotkeys. When blurred, it safely restores them. This is the **recommended primary control** for any immersive experience.

```jsx
// --- In a ViewComponent that needs to capture input ---
const { useRef, useEffect } = dc;

// A reusable hook to handle the logic
function useInputBlocker(viewRef) {
  useEffect(() => {
    const el = viewRef.current;
    if (!el || !dc.app?.commands) return;

    let originals = {};
    const handleFocus = () => {
      originals.commands = dc.app.commands.commands;
      originals.execute = dc.app.commands.executeCommandById;
      dc.app.commands.commands = {}; // Clear command registry
      dc.app.commands.executeCommandById = id => {
        if (id === 'workspace:close') originals.execute(id); // Allow close
        return false;
      };
    };
    const handleBlur = () => {
      if (originals.commands) dc.app.commands.commands = originals.commands;
      if (originals.execute) dc.app.commands.executeCommandById = originals.execute;
    };

    el.addEventListener('focus', handleFocus);
    el.addEventListener('blur', handleBlur);
    return () => {
      el.removeEventListener('focus', handleFocus);
      el.removeEventListener('blur', handleBlur);
      handleBlur(); // Ensure restoration on unmount
    };
  }, [viewRef]);
}

// Example Component Usage
function MyGame() {
  const containerRef = useRef(null);
  useInputBlocker(containerRef); // Activate the blocker

  return (
    <div ref={containerRef} tabIndex={0} /* Make it focusable */ >
      Click here to start game. WASD to move.
    </div>
  );
}
```

### Pointer Lock

The browser API for capturing all mouse movement, hiding the cursor, and providing delta values (`movementX`, `movementY`). This is essential for first-person camera controls in 3D scenes. It is typically used in conjunction with `useInputBlocker`.

```jsx
// --- In a 3D game component ---
const { useRef, useEffect } = dc;

function FirstPersonView() {
  const canvasRef = useRef(null);

  useEffect(() => {
    const canvas = canvasRef.current;
    if (!canvas) return;

    const lockPointer = () => canvas.requestPointerLock();
    canvas.addEventListener('click', lockPointer);

    const handleMouseMove = (e) => {
      if (document.pointerLockElement === canvas) {
        // Use e.movementX and e.movementY to rotate the camera
      }
    };
    document.addEventListener('mousemove', handleMouseMove);

    return () => {
      canvas.removeEventListener('click', lockPointer);
      document.removeEventListener('mousemove', handleMouseMove);
      if (document.pointerLockElement === canvas) document.exitPointerLock();
    };
  }, []);

  return <canvas ref={canvasRef} />;
}
```

## Scoped Input Handling

**What it is**

Controls for listening to keyboard events in a way that respects the component's focus state, preventing global conflicts.

**Use when**

You need to define custom keyboard actions within your component (e.g., using arrow keys to navigate a list) but only want them to fire when the user is actively interacting with your component.

### Component-Level Key Listeners

Attaching `keydown` and `keyup` listeners directly to your component's container. This ensures the events are only captured when the component (or an element inside it) has focus.

```jsx
// --- Inside a component that needs scoped key handling ---
const { useRef, useEffect } = dc;

function MyInteractiveList() {
  const containerRef = useRef(null);

  useEffect(() => {
    const el = containerRef.current;
    if (!el) return;

    const handleKeyDown = (e) => {
      // e.g., Handle ArrowUp/ArrowDown to change selection
      if (['ArrowUp', 'ArrowDown'].includes(e.key)) {
        e.preventDefault(); // Prevent page scrolling
        console.log(`Key pressed inside component: ${e.key}`);
      }
    };
    
    el.addEventListener('keydown', handleKeyDown);
    return () => el.removeEventListener('keydown', handleKeyDown);
  }, []);

  return (
    <div ref={containerRef} tabIndex={0}>
      {/* Your list items here */}
    </div>
  );
}
```

## Ship It: Minimal Starter Flow

1.  To create any immersive experience (game, 3D view, focus mode), start by wrapping your component in a `div` with a `ref` and `tabIndex={0}`.
2.  Copy the **`useInputBlocker`** hook into your component and call it with your container's `ref`.
3.  For first-person controls, add the **Pointer Lock** logic inside your `useEffect`, attaching the click listener to your `canvas`.
4.  If you only need to handle specific keys without blocking everything, use the **Component-Level Key Listeners** pattern instead of the full input blocker.
5.  Programmatically call `containerRef.current.focus()` to activate the input blocking when your component should become active.
