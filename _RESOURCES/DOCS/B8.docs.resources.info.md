
# MODULE 7 — RESOURCES & ASSETS

This module documents the foundational patterns for loading and managing the resources a component needs to function. This includes dynamically loading large, third-party JavaScript libraries from the web—with caching for performance and offline use—and resolving paths to local media assets within the vault so they can be rendered in web-based views.

## External Library Management

**INFO**

Controls for dynamically loading external JavaScript libraries from a CDN (Content Delivery Network) at runtime. This prevents bloating component code by only fetching large dependencies when they are actually needed.

**Use when**

Your component depends on a large library (e.g., D3.js, Babylon.js, Ace Editor) that you don't want to bundle directly, allowing for deferred loading and, with the cached approach, offline access.

### Simple Script Loader

**Description**

A basic function to load a script from a URL. It appends a  script  tag to the document. This is best for non-critical libraries or when offline access is not a primary concern, as it requires an active internet connection on every load.

**Signature**
```typescript
function loadScript(src: string): Promise<void>
```

**Code**
```javascript
function loadScript(src) {
  return new Promise((resolve, reject) => {
    // Check if the script tag already exists to avoid duplicates
    if (document.querySelector(`script[src="${src}"]`)) {
      resolve();
      return;
    }
    const script = document.createElement("script");
    script.src = src;
    script.async = true;
    script.onload = resolve;
    script.onerror = (e) => reject(new Error(`Failed to load script: ${src}`));
    document.body.appendChild(script);
  });
}
```

### Cached Script Loader

**Description**

A more robust loader that fetches a script from a URL, saves a copy to a hidden cache folder within the vault (e.g., `.datacore/script_cache`), and loads the script from the local cache on subsequent uses. **This is the recommended approach** for essential libraries as it provides significant performance gains and enables offline functionality.

**Signature**
```typescript
async function loadCachedScript(src: string): Promise<void>
```

**Code (Pattern from `LoadScript` component)**
```javascript
async function loadCachedScript(src) {
  const cacheDir = ".datacore/script_cache";
  const adapter = dc.app.vault.adapter;
  const safeFilename = src.replace(/[\/\\?%*:|"<>]/g, '_') + ".js";
  const cachePath = `${cacheDir}/${safeFilename}`;
  
  const executeScriptContent = (content) => {
    const scriptEl = document.createElement("script");
    scriptEl.textContent = content;
    document.body.appendChild(scriptEl);
  };

  if (await adapter.exists(cachePath)) {
    executeScriptContent(await adapter.read(cachePath));
    return;
  }
  
  const response = await fetch(src);
  if (!response.ok) throw new Error(`HTTP error ${response.status}`);
  const content = await response.text();
  
  await adapter.mkdir(cacheDir).catch(() => {});
  await adapter.write(cachePath, content);
  executeScriptContent(content);
}
```

## Local Vault Asset Management

**INFO**

Controls and patterns for finding local files in your vault and converting their Obsidian paths into web-accessible URLs. There are two primary strategies for this:

1.  **Direct Path Resolution:** Used when you know the **exact, full path** to an asset (e.g., `_RESOURCES/IMAGES/logo.svg`). This is the most direct and performant method. It directly uses `dc.app.vault.getResourcePath()`.
2.  **Searching by Name (Fuzzy Find):** Used when you only know the **filename** (e.g., `logo.svg`) or want to build a component that is robust to file relocations. This pattern first searches the vault for the file and then resolves the path of the result.

---

### Images (`.png`, `.jpg`, `.svg`, `.webp`)

**Description**

Patterns for displaying static or vector images stored in the vault.

---
#### Pattern 1: By Exact Path

**Use when:** You have a fixed, known path to a specific image, like a component icon or a background texture.

**Code**
```javascript
function resolveAssetUrl(vaultPath) {
  const file = dc.app.vault.getAbstractFileByPath(vaultPath);
  return file ? dc.app.vault.getResourcePath(file) : null;
}

// Example: Displaying a known logo
const logoUrl = resolveAssetUrl("_RESOURCES/IMAGES/logo.svg");
// return <img src={logoUrl} />;
```

---
#### Pattern 2: By Searching (Fuzzy Find)

**Use when:** A component needs to find an image by its name, making it resilient if the file is moved, or when the filename is provided by user input.

**Code**
```javascript
// Assumes a fuzzyFindFile helper is available (see Module 2)
async function resolveAssetUrlByName(filename) {
  const file = await fuzzyFindFile(filename);
  if (!file) return null;
  return dc.app.vault.getResourcePath(file);
}

// Example (from ImageRender):
const imageUrl = await resolveAssetUrlByName("my-diagram.png");
// return <img src={imageUrl} />;
```

---
#### Pattern 3: Binary to Blob URL (For Previews)

**Use when:** You need to generate a temporary, highly performant preview URL, ideal for thumbnails or user-uploaded images. This method avoids the overhead of the `obsidian://` protocol for simple display.

**Code**
```javascript
async function createBlobUrlForFile(fileObject) {
  const arrayBuffer = await dc.app.vault.readBinary(fileObject);
  const blob = new Blob([arrayBuffer]);
  const url = URL.createObjectURL(blob);
  // IMPORTANT: Remember to call URL.revokeObjectURL(url) on cleanup.
  return url;
}
```

### Audio & Video (`.mp3`, `.wav`, `.mp4`)

**Description**

Patterns for getting a playable URL for audio or video files to use in `<audio>` and `<video>` elements.

---
#### Pattern 1: By Exact Path

**Use when:** You are creating a player for a specific, known media file, like background music.

**Code (from `SoundPlayer`)**
```javascript
const file = dc.app.vault.getAbstractFileByPath("_RESOURCES/MUSIC/track.mp3");
const songUrl = file ? dc.app.vault.getResourcePath(file) : null;
// return <audio src={songUrl} controls />;
```

---
#### Pattern 2: By Searching (Fuzzy Find)

**Use when:** You are building a music player that allows users to search for a track by name from anywhere in their vault.

**Code**
```javascript
// Assumes resolveAssetUrlByName helper is defined

  const songUrl = await resolveAssetUrlByName(songName + ".mp3");
  if (songUrl) {
    // Logic to set the src of an <audio> element and play it
  }
}
```

### 3D Models (`.glb`)

**Description**

Patterns for loading `.glb` or `.gltf` 3D model files for use with a rendering engine like Babylon.js.

---
#### Pattern 1: By Exact Path

**Use when:** A component is designed to render a specific, known 3D model, such as in a product viewer.

**Code (from `BabylonLocal`)**
```javascript
async function loadGltfModel(scene, vaultPath) {
  const file = dc.app.vault.getAbstractFileByPath(vaultPath);
  if (!file) return null;

  const modelUrl = dc.app.vault.adapter.getResourcePath(file);
  const result = await BABYLON.SceneLoader.ImportMeshAsync(null, "", modelUrl, scene, null, ".glb");
  return result.meshes[0];
}
```

## Applications

*   **Cached Library Loaders ( [[CODE EDITOR v2]], [[MAP GLOBE]], [[WORLD 888]], [[BABYLON LOCAL]] )**
    *   Uses: **Cached Script Loader** to fetch their respective large rendering engines (Ace, Globe.gl, Babylon.js), ensuring fast reloads and offline availability.
*   **Search-Based Media Renderers ( [[IMAGE RENDER]], [[LOTTIE EXPERIMENT]], [[AQUARIUM]] )**
    *   Uses: **Fuzzy Find and Resolve** to locate local vault assets like images (`.webp`) and Lottie animations (`.json`) by name, making them resilient to file reorganization.
*   **Direct-Path Media Players ( [[ANIMATED CARD]], [[SOUND PLAYER]] )**
    *   Uses: **Direct Path Resolution** because they are designed to play specific, hardcoded media files like a card's video texture (`.mp4`) or a background music track (`.wav`).
*   **Image Preview Generators ( [[RECEIPT TRACKER]], [[OCR READER]] )**
    *   Uses: **Binary to Blob URL** to generate temporary, efficient previews for user-selected or processed receipt images.
