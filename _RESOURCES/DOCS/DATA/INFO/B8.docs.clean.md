## Datacore/Obsidian — Technical Documentation (v0.1)

This document provides a comprehensive technical reference for the Datacore framework APIs. It is designed for developers building components and plugins within the Obsidian ecosystem. Each module section includes a detailed overview, an annotated API reference, type definitions, practical examples, and a list of known consumers.

---

### 1) File System Operations

**Overview**  
This module provides a safe and convenient abstraction layer for interacting with the Obsidian vault's file system. It includes robust methods for reading and writing files (with atomic operations to prevent data corruption), manipulating frontmatter, and managing component state. It also provides a critical utility for resolving local asset paths into web-accessible URLs, which is essential for rendering images, audio, and other media in web-based views.

**API**

- readFile(path: Path): Promise<string>
    
    - Asynchronously reads the entire content of a file at the given vault path and returns it as a string.
        
- writeFile(path: Path, content: string, opts?: { atomic?: boolean }): Promise<void>
    
    - Asynchronously writes content to a file. If opts.atomic is true, it writes to a temporary file first and then renames it, ensuring the original file is not corrupted if the write fails.
        
- updateFrontmatter(path: Path, patch: Record<string, any>): Promise<void>
    
    - Safely updates a file's YAML frontmatter. It reads the file, merges the provided patch object with existing frontmatter, and writes the changes back without affecting the rest of the file's content.
        
- applyEdits(path: Path, edits: Edit[]): Promise<void>
    
    - Applies a series of precise text edits to a file. This is more efficient than a full read-modify-write cycle for complex, non-sequential changes.
        
- readJson<T>(path: Path, schema?: Schema<T>): Promise<T>
    
    - A convenience wrapper to read a file and parse its content as JSON. If a schema is provided, it will validate the parsed data.
        
- writeJson<T>(path: Path, data: T): Promise<void>
    
    - A convenience wrapper to serialize a JavaScript object to a JSON string and write it to a file.
        
- statePath(key: string): Path
    
    - Returns a standardized, safe file path within the vault's .datacore/state/ directory for a given key. Use this to avoid cluttering the vault root with plugin data.
        
- loadState<T>(key: string, defaults: T): Promise<T>
    
    - Loads and parses a JSON state file identified by key. If the file doesn't exist or is invalid, it returns the provided defaults.
        
- saveState<T>(key: string, value: T): Promise<void>
    
    - Saves a component's state as a JSON file identified by key.
        
- resolveAssetUrl(path: Path): string
    
    - Converts a vault-relative file path into a special obsidian:// URL that can be used in src attributes of HTML elements like <img> or <audio>.

### 2) Data & Query Layer

**Overview**  
This is the heart of Datacore's data engine. It enables components to perform reactive queries against vault data. The dc.useQuery hook automatically re-renders your component when files matching the query are created, deleted, or modified. This module also provides utilities for parsing individual Markdown files and performing fast, fuzzy searches across the entire vault.

**API**

- dc.useQuery<T>(spec: QuerySpec<T>): QueryResult<T>
    
    - A React hook for subscribing to a live Datacore query. It returns the query results, loading state, and any errors, and automatically triggers re-renders on data changes.
        
- dc.api.query<T>(spec: QuerySpec<T>): Promise<T[]>
    
    - An imperative, async function to execute a one-time query. Useful in non-React contexts or for background tasks. It does not update automatically.
        
- parseMarkdown(src: string): ParsedDoc
    
    - A high-performance utility to parse a markdown string into a structured object, extracting frontmatter, headings, sections, and code blocks.
        
- fuzzyFind(q: string, opts?: { limit?: number }): Promise<Path[]>
    
    - Performs a fuzzy search (typo-tolerant) for files in the vault by name. Ideal for user-facing search inputs and file pickers.

### 3) UI & Interaction Patterns

**Overview**  
A collection of pre-built, high-performance React components and hooks for common and complex user interface patterns. These primitives ensure a consistent look, feel, and user experience across different Datacore components.

#### 3.1 Interactive Data Tables & Lists

**API**

- <DataTable rows={...} columns={...} />
    
    - A powerful component for rendering large datasets in a tabular format. Key props include:
        
        - rows: An array of data objects to display.
            
        - columns: An array of column definition objects.
            
        - onEdit: A callback function (row, patch) => void triggered when a user edits a cell.
            
        - virtualization: A boolean prop that enables virtual scrolling for rendering thousands of rows with high performance.

#### 3.2 Drag & Drop System

**API**

- useDrag(type: string, data: any): DragHandle
    
    - A React hook that makes a component draggable. type is a string identifier (e.g., 'card', 'note-link') and data is the payload to be transferred on drop.
        
- useDrop(accept: string[], onDrop: (data: any) => void): DropTarget
    
    - A React hook that makes a component a drop target. accept is an array of types it can receive, and onDrop is the callback executed when a valid item is dropped.

### 4) Windowing & Display Management

**Overview**  
This module provides powerful tools for controlling component layout and creating multi-window experiences. It allows a component to switch between different display modes (e.g., fullscreen, floating) and provides an API to dynamically spawn new, independent floating windows that can host any other Datacore component.

**API**

- ScreenMode.get(id: string): Mode
    
    - Gets the current display mode of a component instance.
        
- ScreenMode.set(id: string, mode: Mode): void
    
    - Sets the display mode for a component instance.
        
- ScreenMode.onChange(id: string, cb: (m: Mode) => void): Unsub
    
    - Subscribes to display mode changes for a component instance. Returns a function to unsubscribe.
        
- FreshPip.spawn<CProps>(component: Component, props: CProps, opts?: PipOptions): PipId
    
    - Spawns a new, independent floating "Picture-in-Picture" (Pip) window rendering the given component with its props. Returns a unique ID for the new window.
        
- FreshPip.update(id: PipId, props: Record<string, any>): void
    
    - Updates the props of a component running inside an existing Pip window.
        
- FreshPip.close(id: PipId): void
    
    - Closes and destroys a Pip window.
