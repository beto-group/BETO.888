# Module 7 — Resources, Assets, & External Libraries: Catalog & Applications (Final Draft)

This module documents the foundational patterns for loading and managing the resources a component needs to function. This includes dynamically loading large, third-party JavaScript libraries from the web—with caching for performance and offline use—and resolving paths to local media assets within the vault so they can be rendered in web-based views.

## External Library Controls

**What it is**

Controls for dynamically loading external JavaScript libraries from a CDN at runtime.

**Use when**

Your component depends on a large library (e.g., D3.js, Babylon.js, Ace Editor) that you don't want to bundle directly, allowing for deferred loading and offline access via caching.

### Simple Script Loader

A basic function to load a script from a URL. Best for non-critical libraries or when offline access is not a concern.

```jsx
// --- Can be defined as a standalone helper in your component ---
function loadScript(src) {
  return new Promise((resolve, reject) => {
    // Check if script already exists to avoid duplicates
    if (document.querySelector(`script[src="${src}"]`)) {
      resolve();
      return;
    }
    const script = document.createElement("script");
    script.src = src;
    script.async = true;
    script.onload = () => resolve();
    script.onerror = (e) => reject(new Error(`Failed to load script: ${src}`));
    document.body.appendChild(script);
  });
}
```

### Cached Script Loader

A robust loader that fetches a script from a URL, saves it to a hidden cache folder within the vault (`.datacore/script_cache`), and loads it from the cache on subsequent uses. **This is the recommended approach.**

```jsx
async function loadCachedScript(src) {
  const cacheDir = ".datacore/script_cache";
  const adapter = dc.app.vault.adapter;
  // Create a safe filename from the URL
  const safeFilename = src.replace(/[\/\\?%*:|"<>]/g, '_') + ".js";
  const cachePath = `${cacheDir}/${safeFilename}`;
  
  const execute = (content) => {
    const scriptEl = document.createElement("script");
    scriptEl.textContent = content;
    document.body.appendChild(scriptEl);
  };

  if (await adapter.exists(cachePath)) {
    execute(await adapter.read(cachePath));
    return;
  }
  
  const response = await fetch(src);
  const content = await response.text();
  await adapter.mkdir(cacheDir).catch(() => {}); // Ensure folder exists
  await adapter.write(cachePath, content);
  execute(content);
}
```

## Local Asset Controls

**What it is**

Controls for finding local vault assets and converting their paths into web-accessible URLs for use in HTML elements and rendering engines.

**Use when**

You need to display a local image, play a local video/audio file, or load a 3D model/texture stored in the vault.

### Resolve Asset URL

The most direct way to get a playable/renderable URL for a file when you know its exact vault path.

```jsx
function resolveAssetUrl(vaultPath) {
  const file = dc.app.vault.getAbstractFileByPath(vaultPath);
  if (file) {
    return dc.app.vault.getResourcePath(file);
  }
  console.error(`Asset not found at path: ${vaultPath}`);
  return null;
}

// Example Usage:
// const imageUrl = resolveAssetUrl("_RESOURCES/IMAGES/my_image.png");
// return <img src={imageUrl} />;
```

### Fuzzy Find and Resolve

Finds an asset by its filename without needing the full path, and then resolves its URL. Ideal for robustness if files might be moved.

```jsx
// Assumes fuzzyFindFile helper from Module 2 is available
async function resolveAssetUrlByName(filename) {
  const file = await fuzzyFindFile(filename); // From Data & Query module
  if (!file) {
    console.error(`File "${filename}" not found in vault.`);
    return null;
  }
  return dc.app.vault.getResourcePath(file);
}

// Example Usage:
// const lottieUrl = await resolveAssetUrlByName("animation.json");
// return <lottie-player src={lottieUrl} ... />;
```

### Binary to Blob URL

Reads a local file as binary data and creates a temporary `blob:` URL. Useful for generating immediate previews of images selected by the user.

```jsx
async function createBlobUrlForFile(fileObject) {
  try {
    const arrayBuffer = await dc.app.vault.readBinary(fileObject);
    const blob = new Blob([arrayBuffer]);
    return URL.createObjectURL(blob);
  } catch (err) {
    console.error(`Failed to create blob URL for ${fileObject.path}:`, err);
    return null;
  }
}

// Example: Get a file object from a picker or query, then generate URL
// const file = dc.app.vault.getAbstractFileByPath("path/to/image.png");
// const previewUrl = await createBlobUrlForFile(file);
// return <img src={previewUrl} />;
```

## Applications (per control)

*   **CodeEditor / D3JSTest / MapGlobe**
    *   Uses: Cached Script Loader to fetch their respective libraries (Ace, D3, Globe.gl) and enable offline functionality.
*   **LottieExperiment / Image Render**
    *   Uses: Simple Script Loader (for Lottie player) and Fuzzy Find and Resolve (to locate `.json` files).
*   **Animated Card / Sound Player**
    *   Uses: Resolve Asset URL to get playable paths for local video and audio files.
*   **Receipt Tracker**
    *   Uses: Binary to Blob URL to create previews of receipt images.

## Ship It: Minimal Starter Flow

1.  For any component relying on a large external library like D3.js or Babylon.js, use the **Cached Script Loader** at the beginning of your component's `useEffect` hook.
2.  To display an image from a known vault path, use **Resolve Asset URL**.
3.  To let users select an image or to robustly find an asset by name, combine **Fuzzy Find and Resolve**.
4.  For previews of user-uploaded or selected images, use **Binary to Blob URL**. Remember to revoke the URL on cleanup (`URL.revokeObjectURL(url)`).
