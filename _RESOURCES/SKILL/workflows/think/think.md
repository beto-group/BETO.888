# /think - Datacore Reasoning Protocol

Use this workflow when you hit a complex architectural hurdle, a logic puzzle, or when the user requires "Impeccable Status" for a high-stakes decision.

## 1. Selection Phase
Consult **[[_RESOURCES/SKILL/knowledge/prompt-engineering]]** and select the most appropriate technique for the current context:

| Technique | Best For... |
| :--- | :--- |
| **Context Injector** | Initial task anchoring / Role definition |
| **Example Anchor** | UI Styling / JSON Schema / Specific code patterns |
| **Constraint Cage** | Final refinement / Zero-slop production code |
| **Devil's Advocate** | Implementation Plan review / Risk assessment |
| **Step Exposer** | Complex logic / Math / Multi-file integrations |
| **Persona Stack** | Balance between Design, Engineering, and Simplicity |
| **Failure Finder** | Reviewing broken code / Improving "AI slop" |
| **Output Multiplier** | Creative ideation / Alternative layouts |

## 2. Execution Phase
1.  **Draft**: Write out the formatted template using the details from your current session (Role, Goal, Constraints, etc.).
2.  **Annotate**: Explicitly state which technique you are using.
3.  **Execute**: Output the refined reasoning block.
4.  **Confirm**: Ask the user: "Does this reasoning align with your vision? [YES/NO]"

## 3. Integration
Once approved, update `implementation_plan.md` or `task.md` with the refined logic.
